## November 14 — PMX physics and a proposed reconstruction assistant

The owner asks how much PMX physics HAS supports and wants standardization to
offer a plausible PMX-like physics setup when another format has lost data.
This is a future development request, not an implemented or trained capability.

Current code review at 174f7dc establishes these separate scopes:

- Native PMD/PMX preparation imports renderable mesh, skeleton/skin and
  exportable morphs into the existing standard model. The original staged
  model/textures and editable.blend with upstream MMD properties are retained.
  Preservation in a native/intermediate file is not runtime PMX physics support.
  The portable HAS package currently manages the GLB and report, not the full
  editable Blender snapshot or original physics tables; do not promise that
  those archived declarations survive a standalone portable package.
- HAS can use its own reviewed existing-joint chains or generate weighted
  helpers on supported skinned regions. Its spring runner provides stiffness,
  drag, gravity and supported sphere/capsule collider behavior for declared
  data; fans, preview, explicit Apply/Record, Undo, Off restoration and portable
  playback use the shared HAS system. These do not reproduce authored PMX
  rigid bodies/joints. Generated helper additions currently cannot declare
  their own collision groups; do not imply every helper receives native
  PMX body collisions automatically.
- Original PMX rigid-body shapes, mass, damping, friction/restitution, collision groups/masks,
  motion modes, joint frames/linear/angular limits and spring settings are
  not extracted into a source-bound HAS PMX physics adapter or replayed by it.
  Body Physics uses generated structural proxies and HAS defaults. Native
  PMX 2.1 soft-body/fabric simulation is unsupported. Preliminary asset inventory
  recognizing a 2.1 header is not successful conversion/runtime support.
