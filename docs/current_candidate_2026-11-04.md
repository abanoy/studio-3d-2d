# Current runnable Studio review

`tests/verify_current_candidate.py` freezes the current explicit source inventory
from the current Git checkout inventory, excluding output, engine caches and Python
bytecode. An explicit `--checkpoint` and checksum can still select a checkpoint
inventory. Every current app script must be included. `--inventory-only` reports
hashes without running or certifying any review. It creates cold
folders with spaces and Unicode names, moves them before their first launch,
and copies no developer imports, `.godot`, output, recovery or recent history.
Only declared packed HAS/manifest/reference data transfer for native cases.

The separate checksum-bound previous audio/storage readers remain required by
their compatibility checks. The owner reports those historical backups are no
longer available (2026-11-11). Using the current source inventory does not supply
them or certify a full cold review; their original checks remain unchanged.

The review uses the installed Godot4.6 standard, Python and FFmpeg; it is a
runnable source copy, not a new installer or a bundled runtime. Normal installed
Studio and the frozen web artifact remain separate. Source ZIPs exclude private
native fixtures and test caches. Owner-only sample scenes stay local outside the
source archive. No publishing/deployment occurs.

A declared `override.cfg` gives each review copy its own persistent settings
profile. This follows Godot4.6's
[project setting overrides and custom data directory](https://docs.godotengine.org/en/4.6/classes/class_projectsettings.html).
Core project/source bytes remain frozen. Recovery/recents are already local to
each copy's own output directory; normal preferences and projects are not migrated.

## Acceptance entry point

The verifier runs the included first-movie course and fresh-process Continue,
then actual ordinary Home/New/Open/drawing/Undo/packed Save/Open/Simple Export on:

- a new audio3 end-trim project with original samples and exact PCM;
- a retained MMD scene with baked joint animation and portable declarations;
- an earlier multi-native scene, with all saved world records preserved.
- an assisted-character scene with its saved motion parameters and rendering.
- two current authoring scenes (Miku and an original PMX hinge), where imported
  controller edits must solve and auto-key directly from the freshly unpacked GLB,
  then Undo exactly without access to a native preparation directory.

A separate cold copy runs the complete sound-end-handle workflow with generated
WAVs, including captured release, cancellation, source bounds, Undo, packed HAS
and analytically verified AAC timing. The source inventory currently has593 paths;
the declared checkpoint SHA and private receipts identify each run precisely.

The newer media review uses the601-path PNG-export checkpoint inventory. Separate
cold copies run sound fades (including four fresh storage readers and decoded AAC
ramps) and full/transparent PNG export without FFmpeg, with cancellation and output
faults. An explicit checksum-verified previous audio-reader script is supplied only
as a compatibility-test fixture; it is not an application asset. A seventh packed
case checks audio4 fade editing/removal/Undo, exact PCM and ordinary MP4 resaving.

The next review uses the612-path duration checkpoint inventory. Fresh copies also
exercise orbit navigation with a declared packed Miku input, project-rate presets
with a checksum-bound previous reader supplied as test input, and scene duration
with its four fresh storage readers. Two further packed cases retain exact
fractional-rate audio and scene length while allowing independent drawing,
duration extension/Undo, resaving and ordinary MP4 export. Media checks use each
saved project's actual rational rate and frame count; older48-frame cases keep
their original checks. Reports distinguish this review from earlier artifacts.

Each runtime 3D/audio asset must resolve inside the copy's own newly extracted
cache. All original source files retain their hashes. New preview/export frames
must match exactly; reference-native comparisons retain the established384-channel
mesh-edge bound. Movies are checked with ffprobe. The normal main scene also
launches without test-script flags, exits after a few frames, and has a private-
desktop receipt. A separate probe scene observes automatic Home/recovery without
using the application's test-script startup branch. This does not simulate a
physical BAT double-click.

Actual pinned-engine JSON round trips changed22 final double digits in one MMD
case (maximum1.39e-17), while every affected position/quaternion retained identical
float32 bits. Those are the precision used by Godot's Vector3/Quaternion renderer.
The resave comparison uses exact float32 bytes only for those spatial arrays;
IDs, metadata, time, other fields and decoded audio remain exact. This is a
recorded double-precision serialization limit, not a general numeric tolerance
or a claim of bit-exact decimal preservation. See Godot's
[JSON](https://docs.godotengine.org/en/4.6/classes/class_json.html) and
[Vector3](https://docs.godotengine.org/en/4.6/classes/class_vector3.html) documentation;
the actual local measurements, rather than a generic guarantee, define this gate.

Only after all gates pass should the candidate be copied to the requested Studio
folder with a launch entry, source inventory, build information and a brief guide.
Actual paths/status live in `output/current-candidate-verification.json` and the
dated progress memo, not this procedure description.

Same-machine relocation does not prove clean-PC installation, physical/tablet
comfort, subjective artistic/audio quality, every native format's fidelity or
power-loss recovery. The full original MD/addendum goal remains unfinished.
Audio3 trimmed scenes require this newer build; use project copies with older
installed Studio. See audio_end_trim.md and the MMD import docs for current scope.
