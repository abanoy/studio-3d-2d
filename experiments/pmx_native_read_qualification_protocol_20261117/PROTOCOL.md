This is a non-executable proposal. The sealed reader has synthetic source/CPU evidence; no native file has been selected or read for this protocol. An independent native oracle, comparator, source-handle wrapper, resource runner and public projection are missing. No native command or staging program is provided. The next permitted work is source review and synthetic CPU development of those missing pieces.

## What a pilot could establish

A successful pilot could establish that this exact candidate, under the admitted PMX2.0 profile and for the exact privately identified input bytes, agrees with an independently qualified byte-level witness about the captured native physics tables and bone catalogue. It would preserve the candidate capsule unchanged, including its unqualified flags, and record any earned input-specific witness result in a separate private root report.

It would not establish a valid complete PMX file, skin or IK; material coverage; complete geometry/morph preservation; texture/dependency completeness; physical plausibility; a decoded MMD object provenance join; portable HAS retention; a HAS bone crosswalk; units/basis/height normalization; simulation; or any import/adoption support. No main/REVIEW source changes, source authoring, model saves, conversion, rendering or simulation belong in this pilot. PMX2.1, soft bodies and unrecognized layouts continue to refuse.

The raw reader's current contract intentionally differs from the historical decoded capture. It retains opaque F32 words, including signedzero/subnormal/NaN/Inf payloads with explicit nonfinite indices; the decoded capture accepts finite exact binary32 Python floats and has a128KiB capsule cap. The raw reader's canonical compact metadata ceiling is2MiB. Neither ceiling proves fit beside a256KiB preparation report or1MiB portable project budget. A later decoded join or integration requires separate native provenance, budget and preservation work.

## Independent oracle admission

A source SHA binds bytes; it does not prove that the candidate located the correct tables. Re-reading the same candidate, slicing bytes at its returned offsets, comparing its own counts or names, roundtripping its JSON, or generating expected records from its capsule are self-confirming. None may satisfy native oracle admission. Authored synthetic fixture expectations are also not native-file expectations.

The oracle must independently traverse the complete prefix needed to locate the tables, bind the same source bytes independently, and establish ordered table counts/boundaries and every captured record. It must not import/call/copy the candidate cursor, table walker, offsets, output fields or generated expected native records. Its source, dependencies, separate fixture expectations and raw CPU receipts must be frozen before native use. Oracle invocation must finish and its private witness be sealed before candidate output is created or available. This prevents post-result fitting; source review must additionally show that no candidate result is an input.

The installed MMD Tools source `fb9aafe369025f221bc5a1c952d868260b1a4bb950dc33bca62645b4da454e5a` is a pinned layout reference, not an independently qualified raw oracle. It shares the candidate's layout authority and has replacement string decoding, negative-reference normalization, some truncation fallback and other value repair. Its finite decoded overlap could provide separate corroboration after a separately qualified invocation, but it cannot supply missing original name bytes, malformed negative words or raw-table provenance. It is not executed by this proposal.

An independent normative or secondary layout authority is currently unresolved. Before choosing an oracle, record its actual authority and shared-source limitations. Two independent implementations using one authority can strengthen a declared-layout/input-specific witness; they cannot silently become a general PMX specification proof. New independently authored fixed-offset/word fixtures, plus the existing339-byte manual oracle and full-prefix matrix as regressions, must qualify the oracle's own discovery logic. Include distinct mixed widths, UTF encodings, all restricted prefix branches, raw nonfinite words, invalid selectors/references/counts and exhaustive truncations. Unknown extensions must refuse, never be guessed or zero-filled.

## Private identity and stable reads

Root must privately select one existing original file; no discovery scan, archive extraction, download, installation or source re-authoring is implied here. The private input manifest must bind an exact local canonical path, regular-file/volume/file identity, byte length, full sourceSHA and the admitted limits/profile. Native identity fields stay private. A file name, directory label or header alone is insufficient.

The future read wrapper must use exact source-pinned code and a read-only handle that denies concurrent writes/deletes. It must refuse unsupported file systems, devices, network paths, alternate streams, reparse points/ancestors, identity changes, size/hash changes and sharing violations; no permissive fallback copy or link traversal. Verify canonical handle identity and bounded size before allocation, exact bounded bytes/EOF and sourceSHA before/after, and close all handles in finally. A stable immutable snapshot may be passed to the two reviewed readers, but each witness must bind those exact bytes. The wrapper does not exist yet; this paragraph is a requirement, not observed behavior.

The pure reader accepts at most128MiB of immutable bytes, bounded prefix counts/strings/operations and2MiB canonical compact output, with conservative retained-metadata reservation. These limits do not prove peak heap or wall time: input bytes, decoded strings, capsule objects and serialization coexist. An independent oracle can have different costs. A future runner therefore needs separately enforced owned-job memory and wall limits, bounded logs/output and an actual timeout/resource-failure receipt. It must control only its exact owned Popen/job identity; broad PID termination or interference with unrelated processes is outside scope.

`PROPOSED_RECIPE.json` proposes a one-input pilot,128MiB source ceiling,512MiB owned-job memory ceiling,30s each read/oracle,15s comparison and90s aggregate wall ceiling. These values are proposed limits, not measured or qualified capacity. Canonical candidate output remains at2MiB; oracle and comparison outputs at8MiB each, stdout/stderr at4MiB each, total private outputs at32MiB and public scalar status at32KiB. Exceeding any cap means a refused/incomplete attempt, with explicit retained failure evidence; it never authorizes a cap increase or silent truncation. No output files are created by this protocol.

Exact Python executable/version/architecture, runtime DLLs, imported stdlib/extension code and approved import graph must be frozen. The future wrapper must use a pinned isolated executable and explicit code files, with site/user/cwd import injection excluded and no PATH/shell lookup or native text interpolated into commands. It must not import an installed MMD addon, Blender, renderer or HAS application. The tool manifest, wrapper/oracle/comparator/job source hashes and their synthetic qualification receipts are unresolved readiness gates, rather than invented pins.

## Private comparison

The separate comparator must reject missing/extra/duplicate fields and type aliases, including bool/int and int/float substitutions. Compare exact native table order and indices; section count/data/end offsets and raw count words; encoded names/encoding and decoded text; signed reference values, widths and raw words; unsigned masks; bone flags/layer/optional tail/grant/axes/external key/IK payloads; and every captured body/joint F32 word at its independently witnessed byte offset. Check explicit field-word layouts and derive nonfinite classification independently from the raw bits. No floating tolerance, clamping, None substitution, basis conversion, quaternion repair, name normalization or reordering is allowed. Compare only the captured scope; sourceSHA alone is not whole-model preservation.

Signed minus-one acceptance follows the current reader's documented field-specific layout policy. In particular, weight/grant/IK absence acceptance is not valid skeleton/skin/IK evidence. Different oracle policy must be resolved explicitly before native admission; agreement cannot be manufactured by silently weakening either side. A mismatch, unsupported profile, resource refusal, missing provenance or unqualified oracle leaves the native join unqualified. Both outputs and the failure remain private and unchanged.
