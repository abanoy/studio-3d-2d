# Six-foot model import basis: implementation plan

Status: proposed, not implemented. No application, engine, parser, converter, Git or process inventory was run for this plan. The current optional height-fit UI is implemented independently; it does **not** implement the owner's requirement that standard complete human models have a six-foot basis at HAS user scale 1. PMX reconstruction and the proposed broad model qualification checklist remain separate work.

## Contract and boundaries

For a newly standardized, confidently identified complete human model, HAS scale 1 means a measured reference height of exactly 6 feet = **1.8288 metres**. Scale remains an artist multiplier: 0.5 means 0.9144m and 2 means 3.6576m for that reference. An imported character keeps its proportions; the operation is a single positive uniform basis scale, with no bone, vertex, morph, pose or animation reconstruction.

This basis is intrinsic to the asset under an identity parent. An intentionally scaled group or authored animation still changes its world size. The normalizer must not compensate for a parent's artist scale, remeasure at each frame, move the source origin, or make scale channels nonmultiplicative.

Fresh raw GLB/VRM/PMX/PMD/MDL imports reach the same HAS basis process after their adapters produce GLB + provenance. GMA is an archive/container; qualification belongs to the selected model member, not the archive extension. A whole human in an MDL may qualify, while a VRM-like armature with only a head visible must not. Hair-only models, heads, tools, maps, props, incomplete bodies and ambiguous/multiple figures retain their existing size. Maps keep their independent reference/calibration workflow.

Legacy projects and HAS asset packages reopen with their existing appearance, scale keys, placement, poses and source hashes. Missing new basis data means identity. Existing diagnostic `metadata.import_height` is never reinterpreted as an active basis: its factor has already been applied to old user scale and applying it again would change saved appearance. Loading, Undo, recovery and importing an existing HAS package do not trigger fresh normalization.

## What the code currently does

- `src/import_actions.gd:4,16,28` keeps height review opt-in through `offer_height=false` and per-import context. HAS package import bypasses raw-model import.
- `src/import_height_review.gd:47,63` measures a disposable neutral renderer, then multiplies **candidate.scale** by target/height. Its metadata is a diagnostic decimal record. Thus a fitted model can be six feet while its user scale is different from 1.
- `src/character_height.gd:33` requires exactly two leg chains, an unambiguous head, upright body axis for the suggestion, and visible weighted coverage of head/both thighs. It has a 200,000-vertex limit. The current leg/visible-extent ratio suggestion is .35–.62. The measurement follows visible geometry extrema, including hair, hats and shoes; it is not anatomical stature or a learned human classifier.
- `src/model.gd:451` already evaluates `userTransform * base_root`. `Renderer.prepare_model` and `WorldRuntime.prepare` capture the loaded scene root transform into `base_root`. This is the appropriate composition boundary for a persisted intrinsic basis.
- `src/import_placement.gd:13,36` includes the imported root transform in raw local bounds, then applies the supplied user root transform. Placement must see the same additional basis exactly once.
- `src/storage.gd:57,107,351` and `tools/has_project.py:members` understand project schemas through 8. Old readers permit many extra model fields, so adding an ungated active metadata scale would let them open a project at the wrong size.
- `src/source_secondary.gd:120,144` retains original Source conversion **0.01905** and derives rule length/acceleration using that conversion times actual uniform world scale. The new basis must participate only through the latter. It must not rewrite the Source parameter/report conversion.

`SOURCE_READS.json` binds the exact inspected files and function anchors. These observations do not claim the future design has passed current model or physics tests.

## Preferred bounded representation

Add a validated model field provisionally named `asset_basis`, separate from `scale`. Proposed payload:

```
format: studio_import_basis_1
purpose: standard_complete_human_six_feet
source_sha256: unchanged converted GLB SHA
factor: exact decimal text
target_metres: "1.8288"
measured_converted_height: exact decimal text
source_height / source_unit: preserved adapter facts, or explicitly unknown
measurement_algorithm / reference_pose / classification: versioned facts
decision: automatic-qualified or explicit-complete-human-override
```

The original source/conversion metadata remains intact. Do not call an inferred original unit a source fact. Store diagnostic decimals as text, as the existing height review already does; validate and parse them once. Use a finite positive uniform factor and explicit supported-range checks, with refusal rather than clamping or silently changing the target. The final supported factor range is an implementation guard to choose alongside existing transform limits, not a new owner requirement.

Let `B0` be the unmodified imported root transform, `C` the uniform factor transform, and `U(t)` the existing artist transform. Evaluate:

```
effectiveBase = C * B0
root(t) = U(t) * effectiveBase
factor = 1.8288 / measuredHeightWithB0AtUserScale1
```

`C * B0` scales imported root offsets along with geometry about the original asset origin. Artist root position remains in scene metres. Store the original raw `B0` separately in the runtime object or return it from one configuration helper; never recapture an already adjusted root and multiply twice. New normalized imports start with `data.scale=1`, while raw source units, hashes, local rest data and source bone IDs stay unchanged.

This avoids changing GLB bytes, source identity or native rest/crosswalk evidence. All uniform parent/user/basis scales naturally enter the actual world matrix. In the Source backend, native length L becomes `L * 0.01905 * actualWorldUniformScale`; the latter now includes C. Multiplying `source_scale` by C as well would apply normalization twice. `tip_mass` currently acts as a downward acceleration in the retained 0x31 subset; preserve that existing unit policy and its limits rather than claiming reconstructed physical mass or SDK execution parity.

Alternative: emit a new GLB root wrapper or transformed GLB. This can make asset scale 1 appear convenient, but changes the GLB SHA and may change node paths/IDs or root relationships. The exact Source crosswalk and native admission would require a new authenticated derived crosswalk and fresh fixtures. Rewriting its stored SHA to force admission is invalid. A runtime basis is the smaller first implementation; derived standardized GLBs can be evaluated later as a separate versioned asset pipeline.

## Concrete implementation sequence

1. **Persisted contract first.** Add shared `src/import_basis.gd` and Python parity helper `tools/import_basis.py` for field/schema validation, decimal parsing, identity fallback, capability wrapping and detection. Validate the field in `Model.validate` **before** the model-9 early delegation, and preserve it in all model promotion/install paths. Reject source-SHA mismatches, malformed/unsupported factors and a basis on an environment/group. Record no basis for skipped/ineligible candidates.
2. **Old readers must fail clearly.** Provisionally use outer project schema 9, with `basis_content_schema_version` recording the previous 3–8 schema, wrapping only when an active basis occurs in the scene or a child sequence. Wrap after existing timing/reference assembly. Update `Storage.readable_manifest`, `save_project`, `decode_project` and Python `has_project.members` together. Require the capability for active basis data; avoid authorizing it in an ordinary schema-3–8 document. Unwrap the basis capability before existing timing/reference logic and carry permission only through the same scene's wrapper stack.
3. **Nested/schema combination coverage.** Sequence child schemas currently pass through `Extended.child_schema` / Python counterpart, with child worlds restricted to 4/5 and no nested graphs. Add capability-aware schema inspection there and in `sequence_graph` validation. Both GDScript/Python `Extended.required` must inspect beneath the basis wrapper too, so it cannot conceal a timing requirement. A saved child containing a basis needs its own valid wrapper; a root containing such a child must also reject old readers. Keep timing/reference/sequence resource budgets, duplicate asset identity checks and cancellation behavior unchanged. A standalone package uses the same gated project manifest; its existing `studio_asset_package_1` header can remain because old container readers reject the unsupported manifest schema. Confirm this with real old-reader tests before accepting that choice.
4. **One runtime composition helper.** Add `Model.configure_import_root(rawRoot, definition)` (name provisional) that validates/caches raw B0, computes effectiveBase and sets the root once before inventory/preflight. Route `Renderer.prepare_model` (`src/renderer.gd:203`), `WorldRuntime.prepare` (`src/world_runtime.gd:18`) and raw auxiliary constructors (`wind_helper_candidate.import_actor`) through it. Do not put normalization in `SceneIO.load_glb`: neutral inspection, collision/source readers and legacy consumers need unchanged source scenes.
5. **Immutable instance identity.** Add `asset_basis` to `WorldRuntime.restore_instances`' immutable asset fields (`src/world_runtime.gd:121`), so ordinary pose/scale edits cannot secretly replace the cached base. A deliberate future basis replacement is an asset operation with new preflight, not a dictionary tweak. Root/component animation continues using artist `scale`; do not bake C into body/root keys, pose translations, contacts or GLB skin/rest arrays.
6. **Placement and disposable previews.** `app.append_object_data` supplies `U * C` to `ImportPlacement.plan`, since `local_bounds(decoded.scene)` already includes B0. This must not use `U * C * B0` there. In `shape_comparison.prepare`, the new `Model.definition(actor.source)` currently discards instance extras; explicitly copy the validated asset basis into its neutral definition. `wind_review.begin_preview` (`src/wind_review.gd:168,178`) does the same and also supplies an absolute `live_world_transform`: copy/cache the basis deliberately, but keep that world override as assignment rather than multiplying C onto the already scaled world matrix. Existing clones/probes that copy `base_root` (e.g. thumbnails and world restore probes) keep that effective basis once. Verify every fresh constructor using the source catalogue instead of assuming only the main renderer loads models.
7. **Fresh-import decision before placement/physics.** Add a bounded cancellable standardization step between raw adapter completion and `app.append_object`'s placement/default-physics commit. The transaction has source SHA, request/generation token and project/world revision guards, with no partially installed actor. Only fresh raw model requests enter it. On cancellation, stale request or changed source, add nothing. On valid but ineligible/uncertain classification, add the original-size model with a concise status fact; do not ask the busy owner to resolve every import. Do not normalize twice if the request already carries a validated basis.
8. **UI policy.** The existing scale control (`pose_editor.gd:134,457`) stays an artist scale, with a concise basis-height indication when present. Keep optional custom-height fitting as an artist override: after standardized import, a target T maps to user scale `T/1.8288`. The standardization process should not use the optional old fit checkbox to hide the required basis operation. Advanced metadata can explain retained original height/units and allow an explicit complete-human override where safe; it is not a new mandatory prompt.
9. **Helper-derived asset identity is a required boundary.** `secondary_helper_editor.install` changes `row.source` / `row.sha256` (`src/secondary_helper_editor.gd:628,647`) while retaining the rest of the row. A strict old `asset_basis.source_sha256` would otherwise reject every normalized model after Helper Apply. Extend `wind_helper_candidate.prepare/import_actor` and the install transaction to carry the validated factor through an authenticated derivative relation, after unchanged relevant geometry/root/rest/reference-height evidence has passed. Preserve `measured_from_sha256` as the original measurement identity, bind the new current asset SHA separately, and record parent/current SHA plus the checked derivation proof/report identity. Do not remeasure the posed candidate, blindly replace a SHA, or treat an unchanged node hierarchy alone as proof of unchanged height. Before that proof completes, any transient candidate basis must be tied to the verified source context rather than a falsely authenticated persisted candidate record. Repeated/batch helpers, undo/reopen and helper preview must preserve C exactly. This basis-lineage permission does **not** authenticate a new native Source crosswalk: helper-derived GLBs still fail the current exact native profile and use the existing generic helper path. Make this boundary a release prerequisite, or clearly refuse that operation until it is implemented; do not release silent size changes.

## Classification and unresolved engineering choices

Reuse the current weighted-coverage/leg-chain checks as conservative evidence, not a sufficient automatic human decision. A full skeleton alone proves little: a separate head/hair mesh can retain the entire source skeleton. Require visible complete body coverage and a reliable neutral reference, then classify only the confidently standard complete-human subset. Recognized adapter humanoid mappings can help without relying on English names, filenames or file extensions.

The current visible-extrema height cannot resolve whether a tall hat/hair should count toward human stature. Bone head origins are not head tops either. The bounded implementation should record its exact metric and avoid silently certifying anatomical height when accessory contribution/pose is uncertain. A later explicit anatomical estimator needs its own fixtures; do not invent thresholds here to make every import appear qualified.

Other unresolved cases: bent/posed knees, baked animations or morph defaults at import, stylized/chibi/child proportions, multiple figures sharing a rig, incomplete bodies with misleading skin weights, nonuniform/negative/sheared imported roots, and unrigged complete humans. Preserve size for uncertain/ineligible cases. A voluntary advanced override may identify a **complete** figure and reviewed height; it must not auto-fit known isolated parts or maps. This is an engineering fallback, not a request for new owner decisions.

Measurement must be independent of the current camera, parent scale, playhead, local fan, live pose or queued simulation. Use a disposable disabled-render world with the imported neutral/default reference and user scale 1. Current `CharacterHeight.query` relies on visible-in-tree geometry, so it cannot simply be called on an unattached hidden node and assumed equivalent. Release cameras/worlds/renderers on every path; cache only authenticated measurement facts, never live nodes or private geometry arrays.

## Verification required before release

- Pure contract cases: identity legacy absence, strict decimal/finite/range/SHA validation, no basis on maps/groups, supported wrappers and missing-capability refusal. Match GDScript/Python behavior, including nested timing/reference/sequence combinations, packed/linked packages, cancellation/recovery and old-reader rejection. Existing `test_has_project.py`, `test_asset_package.py`, `test_extended_timing.py`, `test_sequence_graph.py` and storage/sequence readers provide the starting coverage.
- Actual Model/SceneIO cases: multiple complete synthetic humans authored at different scales/units, raw root translations/positive scale, user scale 1 -> measured 1.8288 within the existing **2e-5** height gate, user-scale key playback, parent-group scaling and initial placement. Raw source/GLB SHA/rests/IDs must stay exact; repeated save/open never compounds C. Pose/shape preview sizes must match the installed actor.
- Derived helpers: single/batch Helper Apply and preview on an already normalized model, exact factor/reference-height retention, unchanged-source/current-candidate proof binding, failed/stale/tampered derivations, repeated helper changes, Undo and cold HAS reopen. Ordinary pose-only `Model.new` probes (MMD candidate, contacts, movement/path helpers) keep authored data and existing base_root where needed; they must not initiate normalization.
- Exclusion cases: head/hair-only skin on a complete skeleton, tools, maps, partial Source geometry, uncertain pose/proportions and over-budget input. They must retain original basis/appearance and receive no active normalization field. Source archives must qualify the selected member independently.
- Legacy snapshots: schemas 3–8, prior optional-height-fit metadata, scale keys, contacts, nested assets, recovery and asset import must preserve displayed geometry and authored dictionaries exactly. Reopening must perform zero normalization queries.
- Native physics: retain raw `.01905`, report/wire hashes and fixed clock. Re-run qualified Native8 and experimental chain probes at an actual nontrivial normalized C, plus user/parent scaling and Off/re-enable/reset. Existing two synthetic scale comparisons do not establish this future adapter integration. Full ragdoll, SDK artist parity, all49 rules and PMX rigid bodies remain outside this change.
- UI/teardown/full checks: adapt existing `character_height_smoke.gd`, `height_import_native_smoke.gd`, `height_fixture.gd`, `verify_character_height.py` tests to distinguish automatic basis from optional user fit. Their present assertions deliberately expect no default measurement and therefore must be reviewed, not silently deleted. Keep unchanged source/fixture evidence, strict logs, private desktop, closure and full verification gates.

`unit_basis_examples.py` checks synthetic rational dimensional examples only; its output is not an engine, importer, model-classification or native-physics qualification. No private/native coordinate or artwork data is included in this plan packet.
