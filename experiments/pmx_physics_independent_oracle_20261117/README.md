# Independent PMX raw-table oracle prototype

This is a working source and authored-synthetic CPU increment. `oracle.read_oracle(immutable_bytes)` independently walks the complete restricted PMX2.0 prefix and returns a separately shaped witness of source-indexed bone, body and joint declarations. `compare_tables.compare(candidate_capsule, witness)` maps that witness to the candidate's declared fields and performs exact typed comparison. Neither module opens a file, invokes a parser dependency, starts a process or qualifies a native input.

The oracle implementation imports only dataclasses, hashlib, json and struct. It does not import the candidate, fixture builder, comparator, MMD Tools or an installed addon. It uses its own struct-based integer tokens, record grammar, named table ranges, witness schema and post-walk reference-extent validation. Raw nonfinite words are classified directly from their high bytes. Candidate parsing remains confined to tests, under the existing source SHA pin, after each witness has already been produced. No candidate output, cursor, returned offset or table-walking helper is an oracle input. The comparator necessarily knows the candidate's output schema; that knowledge is not used by the oracle's byte traversal.

The layout was authored from the existing public LAYOUT.md and current documented restricted profile. Both implementations ultimately share the same MMD Tools layout authority. An independently qualified secondary or normative authority remains unresolved. Distinct implementations and synthetic agreement strengthen this declared-layout experiment; they do not establish general PMX conformance, an actual native oracle qualification or independent knowledge of any artist file. Root's reported discovery of possible future files supplied no table expectations and was not used in fixture construction.

The witness retains exact source SHA/length, header words/encoding/role-specific widths, every table's count word and byte range, original encoded model/bone/body/joint names and offsets, ordered native record indices/spans, complete captured bone optional declarations, raw signed references, unsigned masks and every body/joint binary32 word. Signed zero, subnormal, NaN and infinity words remain opaque unchanged bytes. Geometry/material/morph/display payloads are traversed only to locate later tables and check the restricted prefix selectors/references; they are not returned as geometry or interpreted as valid skin, material coverage, IK or physics.

Only exact PMX2.0 globals, widths1/2/4, encodingsUTF8/UTF16LE and declared branches are admitted. PMX2.1/soft bodies, QDEF, unknown selectors/flags, invalid text, negative/excessive counts, invalid negative/out-of-table references, every short read and any trailing byte refuse without a partial witness. The field-specific raw-1 absence policy follows the current documented candidate profile, including its deliberately broad weight/grant/IK absence interpretation. It is not skeleton/skin validity. Texture strings are decoded strictly and discarded; no discovered path is resolved or opened.

Hard capacities are128MiB source,8MiB complete oracle JSON,1MiB per source string,8MiB total source strings and1024 retained UTF8 bytes/name. Typed overrides only lower capacities. Table/nested-count ceilings and20million work units are explicit in `Limits`; retained-output charges also refuse before unchecked accumulation. These are source acceptance budgets, not measured peak-memory, native wall-time, tool isolation or resource-runner qualification. A source can be valid yet outside this profile.

The comparator checks exact source identity, header, all ordered section count words/ranges, model and full captured bone/body/joint data, word layouts and nonfinite classifications. It rejects missing/extra fields and bool/int or int/float aliases. `compare_json` also rejects duplicate-key, malformed/truncated or oversized JSON. Native-value disagreements produce fixed schema paths, without echoing private names, words or paths. Agreement returns a small data-free result with native, physical, simulation, portability and adoption qualification false. Candidate diagnostic work counters and policy-text semantics are not an independently observed table domain; their field/type presence is checked without claiming that the algorithms have equal work or memory costs. Neither input is mutated or promoted.

Tests retain the existing339-byte fixed-offset authored fixture and existing independently authored prefix builder. A new manually dimensioned531-byte UTF16/mixed-width fixture adds two bodies and two joints, duplicate/empty/Japanese names, masks65535/32768,2-byte bone and4-byte body references, signedzero/subnormal/NaN/Inf words and fixed expected byte spans. Those expected spans are literal record-equation results, never taken from parser output. The720-combination matrix covers widths, encodings, additional UVs, all supported skin branches, both tails and optional bone payloads. Each oracle result is checked against authored writer expectations before the existing candidate is invoked. Exhaustive truncations, unsupported selectors, reference/count/resource refusals, deliberate independent-output disagreement, strict types and privacy canaries are included.

Run `python -B -m unittest -v test_oracle` from this folder. No command or activation machinery for that pilot is supplied here. Its native witness, counts, identities, names, raw words and detailed failures remain private under the protocol; this packet contains authored fixtures and procedural source/CPU evidence only. No simulation, conversion, normalization, physical-validity, HAS retention or production-adoption claim follows.
