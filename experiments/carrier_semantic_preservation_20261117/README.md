# Carrier export semantic preservation prototype

This is a separate source/CPU experiment. It leaves the sealed native-normal carrier packet unchanged. No native asset was read, no engine/CIM/Git command ran, and no GLB file was generated. Synthetic tests use dictionaries and component buffers only in RAM.

The future comparison is original B versus an uncorrected carrier export. Enabling custom attributes can change accessor numbers, view numbers, offsets and interleaving. This prototype compares recognized channels by their exact decoded component bytes and order, component type/count/normalization, min/max and unrelated metadata. It also preserves topology, UV/color/joints/weights, inverse binds, position morphs, animation channels, encoded image bytes, materials, nodes/skins and all remaining typed JSON. Dictionaries may change key order; resource arrays other than accessor/view storage stay ordered. Existing references are validated and replaced in an internal comparison tree, never in an input document.

Only the owned new `_HAS_NATIVE_NORMAL_ID` channel and its storage are removed from this comparison. It must be raw F32/SCALAR, positive integral IDs at the existing 200,000 bound, present on every candidate primitive and absent from the original. This proves representation admissibility, not correspondence. A full carrier-ID permutation deliberately passes the non-NORMAL comparison and still reports `native_carrier_correspondence_qualified=false`. The independently derived native/point/exported-primitive relation remains mandatory; the eight ambiguous normal classes cannot be resolved by nearest matching.

NORMAL payload words and NORMAL min/max are explicitly excluded from equality and always require a separate gate. Their component hashes are returned for audit, without arrays. Normal accessor profile/count, unrelated normal accessor metadata and its view metadata remain checked. The prior prototype's exact native-word transport/output gate must still run after any future correction. Neither this comparison nor a matching unit-vector length is native fidelity qualification.

The closed profile accepts one embedded BIN buffer; supported byte/integer/F32 scalar/vector channels and F32 MAT4 inverse binds; uncompressed triangle primitives; authored position morphs; embedded PNG/JPEG bytes; core animation; and only `KHR_materials_unlit` and `KHR_texture_transform`. Unknown extensions, sparse accessors, compression/quantization, external/data URIs, MAT2/MAT3, custom component types, normal/tangent morphs and unreferenced accessor/view tables are refused. This is a preservation comparator for that profile, not a complete glTF validator or general equivalence checker.

Storage layout fields (`bufferView`, accessor byte offset, view buffer/offset/length/stride and buffer byte length) may differ only through checked decoding. Component byte order is exact, including F32 signed zero. Unused BIN gaps/padding and allocation aliasing are representational and are not compared; no rendered channel or image may be unreferenced. All other view/buffer metadata stays typed and exact. Boolean/float indexes are rejected. The strict optional JSON reader rejects duplicate keys, nonfinite numbers and lexical integer `-0` before parsing loses its sign; float signed zero and integer-versus-float metadata remain distinct. Future raw JSON callers must use an equally strict reader.

The synthetic suite covers accessor/view reordering, offset movement, interleaving-to-packed transport, exact input preservation and adversarial changes to each content family. It also proves missing or case-colliding carriers, unsupported profiles, type substitutions and changed raw signed-zero words are refused. There is no launcher, raw GLB parser/packer, writable output API, installed-tool patch or app integration.

Before native use, root must independently review this packet, freeze exact original/carrier file identities and prove both inputs fit this closed profile. A profile mismatch requires a separately reviewed extension, not a waived check. The independent carrier manifest, native exact-NORMAL gate, source/bone/unit/rest/skin identities, five-joint workflow and HAS adoption tests remain separate. Source-unit metadata and the inactive six-foot/scale-1 contract remain unchanged.

Primary schema references: [accessor](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/schema/accessor.schema.json), [buffer view](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/schema/bufferView.schema.json), and [primitive](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/schema/mesh.primitive.schema.json). The prototype intentionally supports a narrower profile than those schemas.
