## Two capture contracts

Both candidates take a **same-call, synchronous snapshot** of raw local/world transforms; they remove duplicate `bone_transform` and `frame64` reads within that call. There is no `await`, inter-tick pose cache or stale authored sample. All69 source specifications, base-scale tokens and expected-world-scale tokens are protected by an exact capture-configuration stamp, so mutating an unrelated cache cannot bypass its former refusal.

The **strict** variant uses a separate unchanged-core69 baseline validator (no simulation state is advanced there), retains all old per-bone scalar checks and projects only the live numerical step. With a synchronous stable scene it preserves the old valid-input calculations/refusals while reducing repeated reads and unrelated step work. It adds explicit finite-composed-transform/configuration guards; arbitrary concurrent mutation between formerly duplicated getter calls is outside the shared same-call contract.

The preferred **closure** variant retains the exact scalar-double **prefix** of old `frame64` for unrelated55: finite origin/basis, positive determinant, first-column length/degeneracy, equal lengths within unchanged EPS and normalized pair-dot shear within unchanged EPS. It retains all69 actual C++ local-parent closure, local-scale checks and world-scale checks against static parent-order products. Those products depend only on authenticated cached base/prefix scale, not authored translations/rotations, and use the same multiplication order as the old full core. They are not a current-pose cache.

**The closure variant intentionally has a different refusal domain.** For unrelated55 it omits the later GS residual/handedness/correction/`Math.goal` mapping and the fully canonicalized scalar hierarchy **origin and orientation** comparisons. Raw parent/local C++ closure does not imply agreement with a recursively canonicalized hierarchy, especially with long descendant offsets. It does not claim identical rejection of arbitrary invalid or borderline unrelated matrices. The CPU packet includes a concrete synthetic matrix whose old pair-dot/scale prefix passes but GS correction is **2.5455844e-5 > unchanged2e-5**; the old v2 rejects it while the raw-only guard accepts it. That is an explicit domain change, not a tolerance waiver or a speedup claim. These extra v2 guards were not the previously shipped Source1 contract.
