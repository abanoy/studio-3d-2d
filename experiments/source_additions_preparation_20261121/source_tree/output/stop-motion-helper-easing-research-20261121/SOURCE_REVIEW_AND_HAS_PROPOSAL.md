# StopMotionHelper easing and smoothing: verified behavior and a HAS remix

Research only,2026-11-21. No GMod/HAS runtime was executed, no application source changed, and no upstream code was copied into HAS. The supplied repository describes itself as a test version. Findings below are pinned to commit548753c9b1fd1a187f42782f8c5ae9ad99aea636 (main, last push recorded2026-11-15). PRIMARY_SOURCES.json records the inspected paths and Git blob IDs.

## Main finding

The owner's recollection is substantially right, with a useful distinction: SMH has numeric per-key Ease in/Ease out controls, while its separate Smooth command requests neighboring keys and removes the original selected key. Easing changes timing between keys; Smooth edits the authored key set. Neither feature, by itself, plans supportive neighboring joints or supplies hair inertia when a model is moved.

The called math function is supplied by Garry's Mod. Its official documentation defines the two parameters as fractions of the start/end of a segment. The pinned implementation preserves endpoints, is linear when both amounts are zero, and normalizes their sum when it exceeds1 before its piecewise calculation. That is a specific timing law, not an arbitrary editable Bezier curve. [Facepunch API](https://wiki.facepunch.com/gmod/math.EaseInOut), [official implementation, lines74–98](https://github.com/Facepunch/garrysmod/blob/167f41541da5a7cff2fc11cf4f5bb19959cbb9a5/garrysmod/lua/includes/extensions/math.lua#L74-L98).

A concrete example of the distinction: the source Smooth command can request keys11 and13 around authored key12 and then delete12. Merely changing key12's Ease in/out does not perform that deletion. HAS should make these two intentions separate and should preserve authored controls by default.

## Recommended HAS design

1. Add Arrive and Leave fields beside the selected authored key. Use clearly labeled0..100percent UI values;12 means12percent, not12times the value. Internally use a finite normalized domain. Show the preceding/following key and channel/clip context so the user sees which interval each value affects. No previous/next neighbor gets an explanation instead of a misleading active control. Existing hold, linear and ease stay exact; custom timing is a distinct opt-in.
2. Show one small timing/speed graph and the selected motion path. Solid markers are authored keys; hollow markers are derived helpers. Keep timing easing separate from optional path rounding and the existing Motion feeling anticipation/overshoot layer. A timing curve controls speed along a path; it does not create whole-body weight shifts or solve moving-model hair inertia.
3. Recalculate smooths rebuilds a complete derived plan from immutable authored controls plus the saved recipe, video rate, clip mapping and generator version. Repeated recalculation with unchanged inputs must be identical and cannot accumulate extra keys. Source-key changes invalidate only owned derived helpers. A failed rebuild must not combine an old plan with newly edited source controls; preserve the unchanged document and report the affected scope. A button that merely clears today's cache should not be presented as the whole new easing feature.
4. Bake into keyframes samples the actual displayed result over an explicit selected range/channel scope and installs ordinary editable controls in one Undo step. Preserve source authored values, endpoints, holds/cuts and unselected tracks. Disable/remove the corresponding derived effect over the baked scope so it is not applied twice. Offer retaining a separate original take/recipe for later edits. Recalculate derived helpers must never overwrite a user's subsequently edited baked keys.

A practical first increment is per-key timing plus non-destructive preview and explicit Bake for camera and selected root/bone tracks. Start path-rounding as a separately named, bounded mode. For original HAS path smoothing, derive bounded neighboring tangents while preserving authored anchors; handle rotations in quaternion space, not Euler component averaging. Do not automatically imitate SMH's delete-the-center-key arc trick. If an optional neighbor-key operation is offered later, preview exactly which keys will be inserted/replaced and make that action reversible.

Define composition once: authored sampling, custom timing, optional existing motion assistance, contact/root constraints and final preview/export must agree. In particular, helper delta calculations must subtract the same baseline they were generated against. Do not time-warp twice, add an already-assisted value again, or recalculate from the previous generated result. Off/default legacy paths should remain unchanged.

## Persistence and Bake contract

Current curve validators accept hold/ease/linear, and current motion settings have exact versioned shapes. Adding ignored fields would let an older reader play a different animation. Use one recognized versioned extension of the existing motion intent, with matching GDScript/Python validation and clear outer-document admission when saved procedural curves become authoritative. Coordinate the next available version with the separate retained-variant/material-visibility proposals; do not independently reuse a reserved schema number. A temporary session preview plus baking plain supported keys can be useful before such persistence is ready, but must be labeled temporary rather than claiming cold retention.

For Bake, preserve actual local-channel coordinates and parent relationships; do not insert world-space samples into a local track or rescale native models again. Include exact authored frames in the bake sample set. Sampling every output frame can match the rendered frames while still differing at subframes, so report and test both if subframe equivalence is promised. Quaternion comparisons should use orientation/angular error; positions use an appropriate distance measure. The unrelated native-normal2e-5 gate must not be repurposed as an animation tolerance.

Preserve the existing per-model32-clip/2048-key limits and1MiB metadata ceiling wherever their current validators apply; preflight the complete result before committing. Sparse per-channel controls avoid copying a full69-bone pose for every changed part. If the requested fidelity/range cannot fit, refuse with an actionable scope/density choice rather than silently lowering precision, skipping keys or raising limits. Keep camera FOV and near/far validity, model transform limits, contact constraints and exact original model/binding/provenance data.

Live body/hair simulation stays separate: Record/Freeze first establishes authored motion, or the smoothing UI refuses the busy context using existing guards. This feature does not enable physics by default, does not coordinate neighboring joints by itself, and does not replace the separately requested HairON response to model translation/rotation.

## Qualification before any adoption

- Pure timing tests: exact endpoints, zero/asymmetric/full amounts, finite bounds, monotone progress, irregular and adjacent key spacing, first/last keys, equal-frame refusal and hold/cut behavior. Any normalization of overlapping easing regions must be visible/documented rather than silently changing entered values.
- Ownership tests: duplicate frame pairs across actors/clips/channels; trim/move/paste and gaps; stable helper addressing; repeated recalculation; stale target/source/draft detection; complete rollback on late failure.
- Bake tests: compare preview against the baked sampler at every output frame and promised subframes, including camera position/rotation/FOV/near/far, sparse bone/root controls, facial channels and parented actors. Unselected motion/contacts, imported setup and source files must remain unchanged. Ensure the derivation is not applied twice.
- Interaction tests: typed numeric values, graph/marker clarity, generated-vs-authored selection, one-step Undo/Redo, cancelled previews, source edits after recalculation, metadata/key budgets and packed/linked cold reload. The separately requested camera double-click behavior should operate on authored keys and not accidentally delete a hollow derived helper as if it were an original key.
- Run the appropriate existing movie/camera/model/shape/clip/native/physics regressions after a concrete implementation. No success, artist appearance, native engine parity or completion-score change follows from this research alone.
