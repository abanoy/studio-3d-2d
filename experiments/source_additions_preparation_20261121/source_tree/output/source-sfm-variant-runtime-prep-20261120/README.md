# Static per-model skins and bodygroups: runtime candidate

Status: authored only; not parsed/run in Godot, not integrated into current Studio. Current 1,084 functional files and active Full are untouched. No private-desktop receipt copies or native assets were added. This is a concrete implementation candidate for the retained-variant exporter being authored separately.

## Handoff and scope

The unchanged schema is studio_model_variants_1 from the frozen Python planner41cc24c4. The final GLB's material indices, primitive/surface order and source-node indices are the identities. No display-name, geometry, nearest-point or texture guessing is used. parameters.json supplies model_variants at its top level; the ordinary model definition hoists it to metadata.model_variants. variant_selection is a top-level per-model studio_variant_selection_1 record. Missing selection means the declared defaults. Model records without this metadata follow the old path unchanged.

The GDS schema admits exact integral JSON numeric values because Godot parses JSON integers as floats; it never admits bool, text or fractional IDs. It keeps the same field sets, numeric domains, groups/choices/surfaces budgets, complete surface coverage, default-material equality, blank geometry definition and controlled-mesh ancestor refusal. Unicode labels stay untouched, with an equivalent escaped-JSON metadata budget.

The first increment changes skins and bodygroups as static per-actor properties. It does not animate variants on the timeline, rewrite source meshes/materials, implement Source skin proxies, or qualify all native feature combinations. Saved documents containing retained variants are promoted to outer project schema10 with explicit variant_capability/variant_content_schema_version markers. The existing <=9 readers therefore reject them instead of silently displaying every variant. Existing model formats stay unchanged, so pose/body/shape/visibility dispatch remains available. Legacy validation receives a temporary stripped view only after the complete variant capability tree is checked; original selections/declarations are restored after existing payload decoding succeeds. Previous schema9 six-foot, schema8 timing, schema7 reference and schema6 sequence wrappers compose underneath. Projects without this feature retain their original schema.

## Concrete implementation

- model_variants.gd validates the declaration, actual imported inventory, complete selection and pure write plan.
- model_variant_runtime.gd captures the actual GLTFState material order and mesh identities before actor parenting. Existing SourceShape.mark metadata plus exact ArrayMesh identity must identify exactly one generated MeshInstance3D per active source mesh node. Ambiguous/reparented placeholder cases refuse explicitly rather than guessing a display name. The complete primitive/default-material table is reconciled against the final GLB declaration.
- A variant-only inert Node3D actor wrapper preserves all imported child transforms and resources. Model.root visibility and parented other actors therefore stay independent from controlled mesh-part visibility, including a source scene whose original root is itself a mesh. Existing non-variant scene roots are unchanged.
- Runtime transactions preflight every retained mesh, material, shared surface resource, current surface override and self-visibility before the first write. They use only MeshInstance surface overrides and local visibility. Shared Mesh/Material resources are untouched. The actor is retained weakly to avoid an actor/runtime reference cycle.
- Existing fade/unshaded temporary material copies are validated, released and rebuilt around a successful static change. Native authored material refs remain distinct from those temporary copies. Hidden retained parts are omitted only from framing bounds through a genuine runtime-owner weak reference; ordinary old assets are unaffected. The existing height query already ignores non-visible meshes.
- Model/world restoration prevalidates selections and applies each actor transaction before committing its data. A later actor failure rolls earlier variant transactions back. The ordinary pose-editor model/world_object history records retain complete before/after model data, so Undo/Redo use the same path.
- The existing save/load code preserves the full model record and metadata; no variant cache, glTF resource pointer or runtime node is serialized. A fresh cold load binds the asset again, validates the saved selection and applies it before installation. Packed/linked metadata copying remains unchanged.
- model_variant_editor.gd supplies a Simple/Advanced Appearance button for the selected eligible actor, with skin and bodygroup dropdowns. Labels preserve original names; an actual blank option displays Hidden. Changes are one ordinary Undo step, not pose auto-keys. The window closes on actor selection change and reflects Undo/Redo.
