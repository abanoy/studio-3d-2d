# Loose-part setup selection candidate

AUTHORED/UNRUN. This is a focused response to the owner being unable to use Ctrl/Shift/range/drag selection in loose-part setup. It does not activate more native joints, broaden the five-owner solver, reconstruct missing physics or change an imported mesh/weight/pose. The all49 native-owner and preview-performance proposals are separate. No current1084 source or receipt was edited.

The selection model stores three distinct things: selected list rows, one focused part for patch/joint refinement, and the range anchor. Existing reviewed inclusion groups and temporary wind choices remain separate. Ctrl toggles rows; Shift selects a range; Ctrl+Shift adds a range; dragging selects/adds/removes a range from its original state; Escape restores that exact pre-drag selection. Disabled rows are skipped. ItemList Ctrl selection applies only inside the list. Existing viewport Ctrl-LMB/WASD camera handling, geometry patch picking and navigation handlers are unchanged.

The adapter delays a burst of focus changes150ms, then runs only the existing ordinary select_part preview for the final focused row. Until that preview starts, old-part refinement, Include/Apply and reset actions are held or flush focus without applying old data. Selection itself never creates a helper worker. Include selected is explicit: every new part passes the existing preview and second review; already-reviewed shared groups are skipped; later failure restores the exact previous inclusion map. A failed synchronous worker launch also aborts and restores the list instead of leaving the queue locked. Apply remains an independent existing action. Excluding one selected area removes its entire shared setup group, which the label/tooltip explains. The module does not choose wind groups or alter native assets.

Both Simple and Advanced use the same selection/inclusion semantics; Advanced only retains its existing numeric refinement controls. No project/schema change is needed because list focus and temporary selection are not saved. Existing successful helper installation remains one undoable world edit, through the unchanged source_check/basis-check/install/Apply functions. Cancellation/close first stops this adapter and discards temporary selection/queued inclusion; existing close/cancel then retains its normal current-project behavior.
