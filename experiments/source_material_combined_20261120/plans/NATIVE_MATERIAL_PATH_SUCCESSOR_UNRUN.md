# Read-only native material-path successor: design only

UNRUN design; no v3 worker, binder profile, test execution or native result is
claimed by this note. The combined v2 failure does not establish whether the B
full_path keys are absent, non-string or legitimate native search-directory
paths. Preserve the original failure and all existing values.

Prefer a read-only preloaded-material provider over adding guessed metadata.
Independently derive the finite ordered bare-name plus relative search-path/name
candidates from c04 material_metadata['metadata']['materials'] and search_paths.
Bind the actual fresh SourceIO parser names/search paths to those same independent
records before using them. SourceIO's TinyPath replaces backslashes and strips
trailing separators; division concatenates, equality lowercases and its Windows
absolute test checks ':'. Do not substitute pathlib normalization or collapse
'.', '..' or repeated separators and call it the same rule.

Observe all four actual appended B Material full_path key presence/types/exact
candidate membership first; retain raw values privately and publish only counts
and hashes. Admit each present string only if it matches the scoped native
candidate rule and is attached to its independently selected actual B ref.
Prevalidate every chosen prospective global TinyPath lookup, including other
Materials and conflicts between native ordinals. Missing, unsupported or
ambiguous state refuses without writing metadata or invoking model import.

Provide only bounded check(path) acknowledgments for those exact witnessed
'materials/' + candidate + '.vmt' requests on already inspected in-memory refs.
The acknowledgment means a preloaded resource relation, not a real VMT file's
existence. No find/read/open/decode method is available. Let the genuine pinned
resolve_model_material populate mdl._resolved_material_paths in normal finite
candidate order; never hand-fill that cache from B or replace the importer.
Recheck actual cache/ref/selected-path observations before all four callbacks.

This requires a separate explicit opt-in material-binding path-witness profile:
retain the unchanged0e/default34 bare-name contract, and admit only an independently
native-derived candidate plus exact actual parser/B ref and unchanged stored
full_path. Do not relax the old check to arbitrary strings. Keep complete raw
material->slot->face/skin and fresh point/RNA stages, actual original mesh/rig
refs, unchanged shaders/packed bytes/owned Library and post-append ID domain.
No rename, slot/skin swap, texture rebuild, file save or historical geometry
identity is introduced. All export/strict non-NORMAL/original2e-5/adoption gates
remain later and unqualified.

The bridge's source1_material/full_path/name preference selects a VMT lookup
before rebuilding nodes; it does not itself establish the actual saved B key
state. The current SDK resolver can produce a legitimate search-path prefix
rather than the all-False provider's bare fallback. This is why actual counts
and a finite native witness must precede the next decision.

The earlier absent-only owned-memory metadata adapter remains a separate
conditional fallback proposal. It may add only genuinely absent keys after
complete native-derived/global uniqueness admission, preserve every present
value, refuse conflicts and record partial writes honestly. Do not execute it
merely because the old strict gate failed. No such write was made here.
