Source-only contract, 2026-11-20. The v3 material-path fix has passed its actual cold SourceIO run and Root preservation/closure audit. This note specifies a **future** explicit buffer-acquisition step. No acquisition, decoding or export was performed to write it. Frozen v3 and shared-resource73 sources remain unchanged.

All Blender links below are pinned to commit `ec6e62d40fa9e9d1bea33ad5d00148c99a4f0832`.

- [`rna_image.cc`](https://github.com/blender/blender/blob/ec6e62d40fa9e9d1bea33ad5d00148c99a4f0832/source/blender/makesrna/intern/rna_image.cc), Git blob `5a7b8777521bfeb7b3e2b31942cf3b2b6bb84cff`: [`has_data`, lines511–535](https://github.com/blender/blender/blob/ec6e62d40fa9e9d1bea33ad5d00148c99a4f0832/source/blender/makesrna/intern/rna_image.cc#L511-L535), only checks already-loaded buffers. `size` acquires an ImBuf. A cold append need not satisfy resource73's `has_data is True` precondition.
- [`image.cc`](https://github.com/blender/blender/blob/ec6e62d40fa9e9d1bea33ad5d00148c99a4f0832/source/blender/blenkernel/intern/image.cc), Git blob `873fbe96e3e5e34e0daa440b50576fd64af5ef1f`: [`load_image_single`, lines4177–4233](https://github.com/blender/blender/blob/ec6e62d40fa9e9d1bea33ad5d00148c99a4f0832/source/blender/blenkernel/intern/image.cc#L4177-L4233), selects the packed entry by view and tile and calls `IMB_load_image_from_memory`. The property is `view`, not `view_id`. Tile `size`/`channels` also acquire buffers; do not read them in preflight.

## Bounded host sequence

1. Start with inspector2's actual unique Image references and packed tickets, after all graph, material, owned-Library and original-ID preservation checks. Recheck these references and encoded data immediately before acquisition. Do not infer image identity from names, equal bytes or dimensions. Cached Image IDs retain Python identity; non-ID tile/packed wrappers use the admitted exact RNA type, actual owner ID and bounded nonzero C pointer, retaining the real wrappers.
2. Before **any** acquiring getter on **any** Image, admit the whole set: local/original `FILE`/`IMAGE`, clean, no animation, `is_multiview is False`, `use_multiview is False`; exactly one actual tile with exact integer number1001; exactly one actual packed entry with exact integer `view == 0` and `tile_number == 1001`; one valid packed pointer and its `image.packed_file` alias. This yields one viewfile × one tile = one packed file in the pinned source. Preserve these fields and pointers afterward.
3. Retain resource73's empty-or-`.png` suffix guard for both `filepath` and `filepath_raw` before warming. A packed PNG with a different suffix is an honest refusal under the current AUTO-image profile, not a reason to rename or rewrite it. Do not access `file_format`, resolution, depth, `is_float`, tile dimensions, pixels or similar acquiring properties during preflight.
4. Bound every packed size before its data getter; read and authenticate encoded bytes, PNG signature/IHDR/CRC and dimensions. Keep the existing profile: encoded and prospective RGBA-F32 bytes ≤64MiB per Image and ≤128MiB for the complete set; dimensions1..16384, depth8, RGB/RGBA, compression/filter/interlace0. The actual inspector2 case observed two unique Images, 1,709,130 encoded bytes and 83,886,080 prospective bytes; this does not prove their buffers are already loaded. No dimension may be trusted merely because it was admitted in an earlier call.
5. Only after the complete-set admission, record nonloading `has_data`, acquire `tuple(image.size)` once per unique Image, then require exact integer dimensions equal to its admitted IHDR, actual channels3 or4, and `has_data is True`. Refuse failures; do not reload, unpack, update, reencode or alter metadata to recover. Recheck all graph/nonbuffer metadata, actual owner/pointer relationships and packed hashes afterward. The expected cache transition is recorded explicitly rather than described as immutable buffer state.
6. Construct the unchanged shared73 `SimplePackedResources(..., allow_shared_images=True)` only after acquisition and rechecks. It performs its own validation. Continue the genuine one-export/session/cache observations, independent carrier/semantic checks, strict non-NORMAL comparison and unchanged `2e-5` normal threshold. Buffer readiness alone qualifies none of them.

## Claims and limits

The new host must report use of image-buffer getters explicitly, separate from the earlier inspection's no-buffer-getter scope. It may state that it made no Python `image.pixels`/`foreach_get` call if that is true. Size acquisition can decode PNGs and allocate an ImBuf; C decoding necessarily processes pixels. The pinned guarded branch explains the expected in-memory load, but this is **not** a universal proof of no C-level file access, transient IDs, hidden decoder work or cached-buffer provenance. Host budgets, owned copies, private-job limits, input preservation and final independent fidelity checks remain necessary. Actual acquisition/export and resource equivalence are unrun at this note's freeze.
