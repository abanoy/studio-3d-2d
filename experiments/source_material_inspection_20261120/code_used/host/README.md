# Separate cold material-only inspection host

This is source preparation. The author did not run its tests, native parser,
Blender, processes, CIM or Git. Root owns every actual qualification. Existing
application files and earlier packets are unchanged.

The host has one narrow purpose: learn whether four materials independently
named by the authenticated native MDL metadata can be appended from the exact
owned historical B and inspected with the frozen simple-graph/packed-PNG-header
profile. It never opens B as a scene, imports SourceIO, decodes native geometry,
assigns native vertex IDs, binds a mesh, saves, renders or exports.

## One cold observation, ordered boundaries

1. The bounded c04 metadata reader authenticates its three in-RAM descriptors
   and derives four distinct native material-table names in original index
   order. It parses material/skin/header metadata, never positions or point IDs.
2. In the same factory Blender process, B2 `enumerate_library` requests no IDs
   and compares the complete exposed BlendData ID-collection census before and
   after. Its summary is retained before any later count/profile refusal.
3. Each exact native name must occur exactly once in the 1..256-material B
   catalogue. There is no first-four, suffix, case folding, translation, saved
   numeric join or name inference. Missing/ambiguous names refuse before append.
4. The frozen inspection helper takes that exact ordered tuple. Every other
   destination list remains empty; assignment of exactly four material names
   is the last statement inside `libraries.load(link=False)`. Returned actual
   refs come from its request list, never a `bpy.data` name lookup. Existing IDs
   must survive unchanged. Added top-level IDs may be only those four local
   Materials and graph-reached local Images; embedded NodeTrees are bound
   separately. A refusal records observed additions without deleting or editing
   them to force success.
5. The frozen helper admits only its complete Output/Principled/optional single
   TexImage graph profile and connected packed PNG resources. Non-ID RNA
   identity uses exact type + cached owning ID + bounded actual C pointer,
   with actual wrappers retained. Cached Material/Image/NodeTree ID identity
   remains exact Python identity. No names or value matches establish identity.
6. All encoded PackedFile sizes are admitted before any `.data` copy: 64 MiB
   per image / 128 MiB aggregate. Header parsing checks PNG/IHDR CRC/dimensions/
   prospective RGBA-F32 budgets. No `image.size`, channels, pixels, depsgraph,
   decoder, path retrieval, unpacking, update, shader edit or full PNG validity
   claim occurs. Paths are inert metadata. All resource arrays/bytes/names stay
   in RAM.

A deliberately unsupported graph is a refusal, not a reason to simplify it.
The worker retains the helper's fixed refusal code and safe census/header
counts. On such a refusal it also attempts bounded genuine node `bl_idname`
counts from newly appended local material trees. This diagnostic does not
traverse sockets/images or read names/image buffer getters, never replaces the
primary refusal, and never qualifies resource/export fidelity.

## Outputs and scope

Worker: `PUBLIC_MATERIAL_INSPECTION.json` /
`PLACEMENT_MATERIAL_INSPECTION.json` under the owned result directory.
Root: `PUBLIC_MATERIAL_INSPECTION_ROOT_RESULT.json`, or an explicitly unqualified
`PUBLIC_MATERIAL_INSPECTION_FAILED_RUN.json`. Private stdout/stderr and Root
proof/launch records remain in the owned job directory.

Public results contain counts, SHA256s, fixed refusal codes and node type
counts, never native arrays, material names, pointers, actual RNA objects,
socket values, packed bytes or saved geometry. Refusal observations copied by
the driver are allowlisted again. Source/read preservation and physical closure
are separate fields: the worker does not certify outer process closure.

Even a successful inspection leaves normal fidelity, strict non-NORMAL
equivalence, resource/export equivalence, dependency closure, native or
historical point identity, mesh binding and application adoption false. It does
not certify absence of transient C-level IDs or reads during library loading.
No historical B mesh is relabelled. A future separate qualification must bind
the inspected resource relation to fresh independently observed native meshes,
repair the old export-hook non-ID RNA identity gates, export under strict
ownership/resource guards, and pass the existing non-NORMAL comparator plus
the unchanged `2e-5` normal gate. None is inferred here.

## Root-only prospective execution

From this directory, Root may run the two synthetic suites in its retained CPU
lane, with bytecode disabled and actual Popen blocked inside the driver tests:

```text
python -B -m unittest test_inspection_worker test_inspection_driver
```

These tests use fabricated metadata/RNA, supplied module text and ordinary
temporary text. The driver suite authenticates the published pure f9 guard but
never invokes an actual native/process/Git observer.

There are 57 authored test methods: 23 worker contracts and 34 driver contracts.
They cover exact native-name subsets including unused catalogue entries,
missing/ambiguous names, early refusal evidence, node-type diagnostics, leases,
all fidelity flags, cross-count/resource budgets, private closure, preservation
ordering, failed-launch handle cleanup and owned/foreign locks.

After independent source review, exact hash pinning and all CPU checks, Root
alone may run:

```text
python -B run_inspection.py --root-lane-confirmed --driver-sha256 <exact-driver-SHA256> --worker-sha256 <literal-worker-SHA256>
```

No visible fallback or automatic second native attempt exists. The material
graph/profile may legitimately refuse the actual B; existing material graphs
and encoded image formats are not known from these synthetic tests.
