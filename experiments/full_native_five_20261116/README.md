closed process, receipt count or released graphics lease. At preparation the
actual run was running. Root alone owns execution and process observations.
No helper has a force, kill or visible-window fallback.

The context gates on actual terminal state before any process query, final report
read or output write. It requires exact launch/birth bytes, source-before and
source-after equality, every current functional member/hash and actual HEAD.
Incomplete/source-changing failures refuse; root must independently review such
a condition rather than fabricate closure. Exact owned process birth identities
and checkout-scoped worker commands must be absent before close writes fresh
raw/flat host records. It issues no termination. Legacy no_process_killed fields
are explicitly scoped to this observer, not deliberate test cancellation or a
wrapper timeout elsewhere. Owner's sibling review remains outside command scope.

The PASS release additionally requires actual coherent terminal PASS, fresh host
proof, an exact separately reviewed current receipt inventory and fresh full
report. It joins canonical log/report suffix and all157keys of the unchanged
hash-pinned verifier. It rehashes every referenced report, physical receipt and
retained receipt alias; checks every isolation/closure flag and run interval;
joins inline receipts; derives actual desktop/job counts; and observes owned
absence again. It permits only the exact source-registered Krita cancellation
(exit2/cancelled/Owned converter cancelled) bound by the fresh report. The pinned
test deliberately requires that one case. No historical192-job count, old report,
late prior child or assumed total is used.

terminal failure, unchanged sources and fresh host proof, plus a separately
reviewed new partial inventory with format
`has_current_failed_full_private_receipt_audit_1`. Its required fields are recorded
in FAILURE_INVENTORY_CONTRACT.md. It reads no final full report. It validates every
collected physical receipt/retained copy and derives current counts. Any late
completion needs an explicit unique path/hash/child-PID pin and the measured
closure window; it never assumes a previous late child. Controlled cancellation
requires the current hash-pinned Krita source and its freshly written phase report.
Unregistered exits or missing metadata refuse for separate root review.
