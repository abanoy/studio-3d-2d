Source tracing explains a fixture interaction. A successful click on the empty Scene-setup view goes through `world_selection.gd` `complete_pick` to `select_entity("")`. Its default `change_workspace=true` calls `app.change_mode(1)` even when the selected entity stays empty. That method posts the Camera instruction via `message()`, incrementing `status_serial`, clearing `status_faded` and displaying a new toast. The original test then refreshes the workspace and clicks the now-current toast rectangle immediately. It assumes that this is still the earlier faded message. The old result contains no actual status/serial payload, so that causal explanation remains a source-supported diagnosis until the new diagnostics execute.

It should expose the fresh Camera message while retaining the original 31/1 outcome if this diagnosis is correct.

The final check retains the real Canvas-click condition and adds requirements that the snapshot was faded and that refresh preserved the faded state, zero alpha, exact text and serial. The other 31 predicates remain exact. No wait occurs after refresh, so a refresh-caused resurrection cannot be hidden by waiting again.
