# Bounded native Source port review

The existing actual evidence establishes scalar64 candidate `14053abf4b00c50909468d41372ce77c826bf0ec0b895bec19418a5961b4fae3`, actual Model FK transport, and native8 FrontHair1 leaf behavior in the exact Junko69-bone/49-rule family at Source conversion scale 0.01905. It does not establish a 49-rule native runtime. The first production route should identify that family while executing only selected native8 and leaving the other 48 rules retained and inactive. Preserve `full_native_rule_layout_verified=false`, the inert native report, and the existing source crosswalk. A separate runtime descriptor can identify the bounded live implementation without rewriting imported evidence.

The root's initial implementation decision is narrower than the future interoperability cases below: use native8 only when this exact family has no generic secondary chains, retain Spring for all explicit helpers, add no persistent native configuration, and start only through the explicit Hair & clothes toggle. Refuse native setup while a primary body is running and refuse enabling a body while native8 is active. Body interoperability remains a later separately qualified increment. The first port's body test therefore asserts atomic refusal and unchanged ownership; it does not claim the moving-body overlay is implemented.

## Concrete port boundaries

1. `Model.apply` installs `live_pose` as the complete pose, not a sparse layer. Each native step must start by applying the current authored pose or current primary-body pose, construct its world-space goal from that baseline, and overlay only native8's rotation into a deep copy of the complete baseline. Keep every authored position and all 68 unrelated bones. Never feed the last simulated leaf orientation back as its next authored rest. The proven adapter's delta is `base_rotation^-1 * parent_world_rotation^-1 * desired_world_rotation`; retain its actual parent/local/world closure guard and scalar64 float32-boundary correction limit.

2. The generic `SecondaryLive.advance` additionally fades its result over 0.35 seconds and caps offset rotation at 180 degrees per second. Passing a native result through that loop would change the verified trajectory. Give native output a separate absolute-pose branch. Preserve the generic Spring branch's existing behavior, including VRM and manually configured helpers. An explicit generic helper override should win over automatic native metadata discovery.

3. Existing `PhysicsEditor.sync` and `enable_hair` test only `has_secondary_rig.chains`. Without extending these availability gates, an untouched exact Junko model never reaches a native factory. Make native availability part of the same toggle decision while preserving ordinary helper setup for unavailable or unsupported models. The imported metadata itself must not turn simulation on automatically.

4. `SecondaryLive` and body activation inspect `runner.chains[*].ids`; fan force sampling also uses each chain's first joint binding. Supply an honest selected-leaf adapter for these contracts, or use explicit native branches. Do not expose all 49 retained owners as driven IDs. Overlap with a primary body is a conflict only when the selected driven leaf is also body-owned. A body owning ancestors may still supply a changing baseline, subject to actual adapter/context qualification.

5. Candidate state is per instance, keyed by exact actor/source/binding identity. Two actors sharing one GLB need independent solver states and tick counters. Creation, re-enable, stop, dispose, source reimport, skeleton replacement, supported uniform scale changes and time discontinuities must reset or recreate state. Never keep a simulated offset when Off restores a different keyed pose. Capture the incoming live ownership state before native setup so cancellation and errors restore it atomically, including a still-owned primary body.

6. The project physics clock is 120 Hz; candidate `step` advances a fixed `1/120` and requires sequential integer ticks. A port must explicitly enforce that delta or implement a separately tested accumulator. Editor timeline frame may stay fixed while simulation continues, so repeated frame numbers alone are not discontinuities. Recording time advances fractionally and must not reset every time it crosses a display-frame boundary. A genuine seek, backwards time, skipped recording time, changed playback epoch or root/profile change needs a reset based on a clearly owned clock epoch.

7. Reuse `SourceBindings.resolve/current` for authenticated native catalogues, float32 words, crosswalk graph/skin slots, imported IDs and parent links. The CPU helper is an additional necessary-gate review, not a replacement. Avoid hashing/parsing the GLB on every 120 Hz tick; use full resolution at setup/invalidation boundaries plus cheap live-object/context guards during steps. Do not trust a serialized claim that a live binding is current.

8. Retain the exact compatibility exception established by the native leaf probe: at most one exact native `PhysicalBoneSimulator3D`, direct internal child of the selected skeleton, no script, not simulating, no physical bodies anywhere in the actor, and no other modifiers. Godot may legitimately expose `active=true`. Keep rest-only, final-pose, enabled-bone and topology restrictions. A new production exception needs tests for foreign script/modifier/body and incomplete subtree scans.

9. Conversion scale and actor scale are separate. GLB positions already contain 0.01905; the adapter scales native rule length and mass-acceleration once by `0.01905 * uniform_world_scale`. The native rule forward axis is Z. Existing fan fields produce world-space vectors; define whether those are world acceleration or native-unit acceleration before applying a scale. Do not apply Source conversion twice. Actual existing results cover controlled synthetic acceleration, not calibrated fan speed or SFM parity.

10. The existing generic error handler calls `freeze`, which can author the latest simulated pose as a draft. Native invalidation should explicitly stop/dispose and restore the authored or current body baseline rather than silently freezing deformation. Record is a separate authorized authoring action: its existing complete FK capture can retain native motion after the lifecycle is proven. Metadata must stay unchanged when adding, removing, recording or undoing this runtime overlay.

## Meaningful production checks before activation

| Check | Required observable result |
| --- | --- |
| Qualified family and negative admission | Exact actual GLB/native profile reaches only the bounded leaf route. Custom Source scale, another MDL, bad flags/words/wire, missing live mapping and conflicting contexts preserve the generic/helper route or refuse native setup without actor mutation. |
| Generic regressions | Existing VRM0/VRM1 and manual helper fixtures keep their runner selection, complete poses, airflow response, Record and Off behavior. Exercise actual generic scenes; the CPU routing result does not prove them. |
| Authored overlay | At keyed non-rest frames 12 and 24, unrelated 68 bone poses and every position stay exact. The selected leaf changes only by the measured native delta. |
| Weighted geometry and Off | The known 9,509 zero-leaf-weight vertices remain exact, 152 affected vertices respond, 144 shared-weight vertices use actual Skin bind slots, and clearing the overlay restores every privately captured weighted point exactly. |
| Primary body baseline | A moving body-owned ancestor remains current; the selected leaf overlays that pose without replacing the body's transforms. Turning hair Off keeps body ownership and restores the body's current leaf baseline. Direct selected-bone ownership refuses atomically. |
| State lifetime and clocks | Two actors, repeated Off/on, cancellation, deletion, reimport, root-scale/context changes, seek backward and recording discontinuities cannot reuse stale state. Repeating an identical reset cycle yields the same result. |
| Fan units and direction | Zero/disabled/outside-field fan matches control. Positive and negative directions produce the expected signed response; strength changes remain finite and bounded. Test a rotated/moved root and scaling separately from conversion scale. |
| Invalid step rollback | Nonfinite/unsupported frame, invalid delta, source/context change or solver error leaves no partial bone/data edits and restores the correct authored/body state. No implicit frozen draft is created. |
| Record/Undo/persistence | An explicit take captures ordinary FK keys; Off and Undo have the established behavior; HAS save/reopen and a short movie read those keys without a live native solver. Imported jiggle and full-layout flags stay inert/false. |

Parent-child native chains, all 49 rules, broader models, native friction/base constraints, parent dynamics, SDK/SFM parity and artist parity remain separate increments. Do not infer them from the bounded leaf port.

## CPU control packet

`admission.py` validates necessary metadata conditions without opening geometry or creating live bindings. It reconstructs all 49 authenticated float32-prefix/wire records, checks exact family/source scale and actual measured native8 parameters, preserves the generic override, and returns only `eligible_for_native8_live_checks`. It deliberately always reports `runtime_admission_proven=false`.

`controls.py` reads the one already retained parameter report at its exact SHA256 and executes 186 controls. The accepted case uses a synthetic summary of the previously proven live resolver. Negative cases cover every rule's flag mutation and a self-consistent altered value/word/prefix rejected by the fixed rule wire, typed false/counts, nonfinite values, selection domains, overrides and live-context claims. Input metadata and all argument dictionaries are checked unchanged. No real binding, generic scene, product lifecycle, engine parse or runtime behavior is established by these controls.
