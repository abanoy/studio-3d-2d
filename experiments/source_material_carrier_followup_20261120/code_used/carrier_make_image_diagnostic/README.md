# Bounded shared make-image failure forwarding

Source-only successor to the frozen empty-material-extension carrier helper. The old helper and all 45 test methods are retained exactly under bases/. No tests or native processes were run by this author. Root qualification is separate.

On an existing export failure, the helper reads only owned ordinary instance dictionaries for session.shared_cache.public_make_image_failure. An admitted report is copied into activity.export_make_image_failure: finite format/status/refusal labels, independent capped count and exactly 26 booleans. No bytes, hashes, image names, buffer indices, pointers, object representations or SDK error messages enter this report. A malformed report produces a fixed UNADMITTED_SHARED_CACHE_DIAGNOSTIC marker; absent observation stays absent.

This does not change the source guard, H/R/S admission, operator profile, resource identity, empty-extension opt-in, scene restoration or comparison criteria. The original exception remains primary. A separate diagnostic-copy failure cannot suppress cleanup or replace that error. The existing material and latch reports retain their own counts.

Authored controls: 52 methods (45 text-exact predecessors plus seven focused methods). They cover copy independence, typed fields and claims, absent/unavailable/capped observations, foreign property/key avoidance, separate counts, continued copy after a different diagnostic failure, and primary/secondary cleanup preservation. Tests use fake scenes and temporary synthetic files only.

The actual V9 failure remains unqualified: no GLB was produced. This successor diagnoses the exact make-image predicate without asserting a cause or permitting its result. Resource, normal fidelity and application adoption remain unqualified.
