# Strict material guard — diagnostic-only successor

This packet observes the first actual material-guard refusal while preserving the prior strict material method. It does not admit extensions, additional textures, repeated material hooks or a broader shader profile. The prior material function body is byte-exact after its rename to _material_strict. Its new outer wrapper only attempts safe failure metadata and re-raises the same original exception. Diagnostic failure is suppressed; the original failure and existing H failure latch remain authoritative.

The new owned resources.public_material_failure field begins as None. Its first failure holds one safe fixed-schema observation; later failures increment a counter capped at128 without replacing the first observation. Four original material-guard Refusal codes are allowlisted. Other Refusal strings/exception classes/messages are not copied.

Material observations contain finite type labels and fixed booleans/counts only: actual expected material type, source graph cardinality, original guard fields, positive TextureInfo identity/key match counts and repeated source/material counts. Extensions are restricted to fourteen public KHR token names, with bounded dictionary counts and thirty-nine known payload field names whose TYPES alone may be reported. Unknown names/values are never emitted. No RGB values, numeric factors, filenames, material names, private class names, object addresses, payloads or native arrays enter the report. The Extension-like plain instance dictionary is diagnostic shape only, never resource identity or admission. Custom attribute handlers and dictionary descriptors are rejected before dictionary access; other properties are not evaluated. The report does not claim that these hook-time values are final serialized values.
