## Stable scale admission

The core requires exact size equality. Raw float32 basis lengths can vary slightly as an authored root rotates even when its logical scale is constant. The bridge therefore caches the admitted positive uniform Skeleton prefix scale and each Model base scale. Every tick still checks observed local/world scales, uniformity, handedness, shear, parent-local closure and all69 scalar baseline worlds against the existing2e-5 boundary. Only after these checks does it supply the identical cached scales to the unchanged core. Solver sizes never follow measurement noise and never rescale in place.

An exact authored `actor.data.scale` token rejects explicit manual resizing. Parent/Skeleton changes beyond the existing scale boundary also refuse before commit. **An ancestor or keyed scale drift smaller than2e-5 can be indistinguishable from basis roundoff under the current transform-only contract. This draft does not claim to detect every such edit.** It admits that bounded transform residual while keeping core sizes fixed; it does not implement animated resizing. Full source authentication still occurs on create/reload; interior file edits preserving header, length and mtime remain outside the continuous cryptographic guarantee.

In particular, sampled root-key scale can change without `data.scale` changing. Detecting arbitrarily small sampled changes would require a resolved authored-scale token/time from the wrapper, followed by its own contract and tests; this draft leaves the runtime signature unchanged.
