# Minimal inert native-jiggle metadata draft

This is output-only source and authored CPU evidence. No production file, approved runtime, native asset, Git object or HEAD is changed. The earlier `source/` sidecar planner and its CPU/review evidence remain historical; only `minimal-source/` is the current candidate. It has no sidecar or pending-publication API.

The verified decoder is copied byte-exact (`3a6f690a…`) and never imports SourceIO. The adapter uses raw MDL49 bone-relative prefixes, not the pinned SourceIO Bone constructor's defective procedural-type field. It keeps native bone flags, numeric type5 and rule flags separate, preserves all29 named float32 values/words, and records unknown bits with full-layout verification false. It never enables Hair&clothes, creates runtime bone bindings, changes source bones or maps values to a solver.

## Exact byte and fallback contract

`inspect` validates source hashes, finite raw values bounded to the proposed absolute1e6 admission range, maximum4096native bones/128rules, native integer identities and the unchanged verified prefix decoder. Unsupported optional layouts/counts/values return an explicit unavailable status; values are never clamped and no partial rule list is published. Source/native identity violations remain errors.

The standalone metadata gate is its actual canonical compact UTF8 encoding with ASCII escapes and one final LF, inclusively at131,072bytes. The whole-report gate is the **final nested** `json.dumps(ensure_ascii=True, indent=2)` UTF8 encoding, with the caller's actual LF/CRLF translation and no final newline, inclusively at262,144bytes. Measuring a standalone compact proposal cannot prove full-report admission.

If both gates fit, retain all exact inert metadata inline. Otherwise omit the entire optional numeric branch and retain a bounded explicit reason with original/native SHA, metadata-candidate SHA/byte count, rule/bone counts and zero retained rules. A report-size omission also records separately named full-report candidate bytes and line ending. The original MDL/preparation bundle remains the source of truth; no new metadata file is promised. If even status cannot fit, preserve the original valid report exactly and retain the bounded reason in its conversion log. An original report already invalid or over256KiB retains its prior limitation; this adapter does not compact it, delete fields or claim to fix it.

`src/pose_editor.gd::definition()` checks the actual supplied report file length before parsing, then stores the **whole parsed report** in `data.metadata.native_parameters`. Native fields therefore live under `data.metadata.native_parameters.native_parameters.source_jiggle`. Its256KiB admission stays unchanged. `src/model.gd` currently accepts metadata as a dictionary; no new runtime adapter is implied. `tools/has_project.py` independently caps the entire project JSON at1MiB. Passing a per-model report cap does not prove multi-model packed/linked save admission; that existing project cap is not raised or bypassed.
