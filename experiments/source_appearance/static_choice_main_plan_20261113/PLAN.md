# Small main port: choose a Source model's static appearance before import

This is an output-only plan, grounded in the current importer and published source/evidence. It changes no main or prototype file and runs no converter, model, native viewer or graphics process. The exact read files, hashes and observed HEAD are in SOURCE_CONTEXT.json. The helper-preview port is a separate uncommitted change; it does not add Source skin/bodygroup selection.

The next increment should add a small appearance section to the existing Source import dialog, then prepare one new static GLB through the normal Add model path. It should preserve the ordinary default conversion and BSP-prop branches. Existing edited objects must not be silently reconverted. No project format, Model rig, renderer or animation-track change is needed for this increment.

## Native catalogue and UI contract

The metadata result should bind original_source_sha256, normalized selected_member (or loose filename), native_mdl_sha256, native version, exact numeric skin rows/material references, bodygroup/choice indices, raw names plus byte hashes, native vertex counts and true blank flags. A UI context additionally includes the member, catalogue digest, mount-plan digest and generation. Reset choices when the member changes even if another member has identical MDL bytes: resource search context can differ.

Reuse the strict prototype request format studio_source_appearance_request_1 with exactly format, source_sha256, native_mdl_sha256, skin and bodygroups. The enclosing conversion request already retains source_member and mounts; do not add unknown fields to the strict appearance request without an explicit schema version. Numeric option metadata, not display names or translated labels, supplies selection identity. Never derive blankness from a name: the broader Keiki main has a choice literally named blank with14521 vertices.

Use an appearance section inside the existing dialog. Show Skin1/default, Skin2, Skin3 with native index metadata; avoid inventing color names from filenames. A group with exactly one visible/one true blank can use a simple present check; generic multi-choice groups use an option list. Confirm is disabled for an explicit all-blank result, with plain text explaining that at least one part must remain. The worker remains authoritative. A failed catalogue or unsupported native version leaves the old default route available and explains that alternate appearances could not be reviewed. A selected alternative must never silently fall back to default after a worker refusal.

Untouched/default controls should omit --appearance so existing default and BSP behavior remains comparable. A conversion-specific request is written into a fresh owned folder only after the user confirms this dialog. Rehash source/member at submission and again in the worker. The late result must still match the original import generation, member, checksums and current allowed import context. Cancel/failure leaves the current world, camera, drawings, audio, history and selection intact; generated diagnostic files remain local. Success enters the existing normal Add model/height-review/placement route and creates the existing single import Undo.

The header catalogue can predict choices but cannot certify Blender container correspondence. The existing validator must still check unique group names, matching native/converted variant counts, actual blank/object ownership, equal skin-row widths, unambiguous default columns and native default slot identity before changing even the disposable model. Refuse duplicate-name aliasing, nonidentity/ambiguous skin-column remaps and missing objects rather than infer their meaning. A default import may remain available under its historical scope without claiming that explicit alternatives are safe.

Respect existing budgets. Expanded catalogue strings must not create an unbounded result, and the report must remain compatible with the256KiB parameter-adoption cap and project metadata budget. Nitori/Keiki fit easily; wider future cases need size checks. Do not silently truncate catalogues into a successful incomplete report.
