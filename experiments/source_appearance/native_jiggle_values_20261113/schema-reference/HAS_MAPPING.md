Existing HAS solver boundary and next bounded Source jiggle work

This is an output-only design proposal. It changes none of the current static appearance/resource-path fix or its expected results. No native simulation or artist comparison is claimed.

`secondary_rig.gd` currently adapts VRM0/VRM1 and HAS helper extras, not Source procedure type5. Its retained contract uses unique native-derived runtime bone/path identities, at most128chains and512rotating joints, finite settings, acyclic hierarchy and no shared rotating-joint ownership. `secondary_spring.gd` runs explicit fixed steps (positive, at most1/60s) in a scratch skeleton and emits ordinary native-ID FK offsets. Positive uniform scale and nonzero segments are required. `secondary_live.gd` layers that output over authored/body poses, participates in existing wind/Record and clears live offsets when stopped/disposed. The current Hair&clothes restoration behavior must stay intact.

Source's per-bone yaw/pitch/along-axis stiffness+damping, angular/length constraints and base-spring/friction fields have no exact representation in the current isotropic stiffness, drag0..1, gravity and radius tuple. BOING has no current counterpart. Source stiffness/damping values must not be copied into Godot drag/stiffness and labelled native behavior. In particular the current one-bone virtual tail follows localY; the Source native tip axis and imported rest-basis conversion need explicit provenance before deriving an endpoint.

Proposed sequence after the static port passes:

1. Preserve bounded exact source-jiggle metadata and show supported/unsupported status, with no automatic solver activation or authored pose changes. Store original/native MDL hashes, version49, source-reader revision/layout, distinct native bone flags/procedure type/jiggle flags, each native index/parent and all available finite parameters. Preserve unknown flag bits and missing-layout reasons. The pinned SourceIO type-slot/layout defects need explicit handling; do not modify the approved runtime silently.
2. Establish an unambiguous native-index→exported glTF joint→validated HAS runtime binding. Names are explanatory labels, not the mapping algorithm. Refuse duplicate/missing/offset-only rotating bindings, mixed transforms, parent cycles, excessive counts, or overlap with another active body/helper solver. Match existing128chain/512joint and capture/Record/Undo/Off lifecycle limits.
3. Read actual parameters for a small named JunkoHair subset before choosing a simulation subset. FrontHair1(index8,parent7) is a concrete independent target;17→18 and26→27 are independent hierarchy cases. Their current metadata does not reveal flags or numerical values, so none is yet certified as a flexible-only/constraint-free example.
4. If previewing through the existing HAS spring runner, present it as an explicit reviewed approximation with a documented parameter mapping and unsupported constraint list. An exact Source subset instead needs a separate bounded port of the Source algorithm, operating on scratch state and emitting the same FK overlay contract. Neither route should silently alter original bones/weights, enable on import, manufacture fan motion, change the current body solver or commit simulation to keys without Record.

Units and admission proposal: preserve finite native floats first; reject NaN/Inf and noninteger IDs/flags. Use an explicit versioned named-field representation, at most4096native bone identities and128admitted jiggle records, with a128KiB encoded jiggle cap and the existing full parameter-report256KiB admission still enforced. Preserve signed finite values within an explicit metadata admission bound of1e6; larger or invalid values leave this new optional branch unsupported rather than being clamped. Counts/serialized-byte caps are proposed HAS operational budgets, not claims about the native MDL format. Do not silently clamp source values. A future simulation profile may require nonnegative length/coefficient domains and ordered angle/base limits; unsupported but finite authored values should be preserved with an explicit reason and stay inactive. Lengths/offsets and acceleration-like gravity parameters must use the actual conversion scale and Source-to-HAS basis, not a hardcoded inch conversion. Any dimensional interpretation of Source stiffness/damping is an inference from the SDK algorithm, not a replacement for a matched reference run.

Verification should separate exact metadata round-trip and binding/refusal controls from dynamics: deterministic repeated fixed steps; parent/root movement; scale/basis conversion; finite output; true fan hit/miss; no source/history mutation during transient preview; Off restores authored current-frame poses; cancel/close/stale results cannot resurrect; explicit Record plus packed/linked cold HAS/export reproduce the captured offsets. A native Source reference run remains necessary before a fidelity claim.
