## Proposed behavior

The ordinary Source import dialog gets an optional **Choose skin and parts for
this import** section. A separate metadata-only Python child reads the selected
MDL49 tables; it never extracts resources or starts Blender/SourceIO. Controls
reset on member change and have a unique result path. Close/member changes
invalidate the job; a30-second UI timeout leaves the default route available.

Defaults, untouched controls, maps and BSP props keep their existing worker
route. A changed skin/bodygroup creates the already published
`studio_source_appearance_request_1` request. The original file SHA and selected
MDL SHA bind it. Numeric native identities, not display names or array order
guesses, select each part. The worker validates every selection before changing
even its disposable Blender objects. It refuses unknown/out-of-range or
ambiguous correspondence, split duplicate skin columns and all-blank geometry.
An explicit failed choice never silently converts the default instead.

This chooses one static appearance for a new import. Existing actors, their
authored poses, physics, Undo and project data are not reconverted. The ordinary
successful GLB adoption path remains in `source_import.gd`. The existing metadata
and portable packed-project reader remain responsible for adoption/persistence;
this task has not exercised either path in Godot.

## Bounds and explicit limits

The catalogue reads only the common240-byte MDL49 header prefix, material64,
skin-u16, bodypart16 and model148 tables. Full native geometry/bones/weights/flex
rules/material resources are not parsed or certified. Tables must be in-bounds,
nonoverlapping and within count budgets; duplicate native group names refuse.
Raw name bytes are reversible Latin-1 with their SHA, separate display text and
numeric identity. The author's text encoding is unverified. Exact/suffix-pooled
strings outside structural tables remain supported. A choice called `blank`
with nonzero native vertices remains visible; only zero vertices means blank.

Metadata acquisition allows inputs up to512MiB, selected MDLs up to16MiB,
GMA index reads up to4MiB and a complete catalogue up to256KiB. Hashing is capped
at each admitted size+1; loose reads are capped16MiB+1. GMA selected bytes and VPK
payloads have CRC checks. Input SHA/size/nsmtime are rechecked in `finally`, even
after a parser refusal; a VPK segment read gets its own before/after receipt.
Unselected GMA content CRCs/resources are not inspected or claimed complete.
The existing GMA inventory parser retains its own entry/count behavior; large or
slow indexes may hit the explicit metadata timeout and keep defaults available.

The optional chooser currently supports loose MDL, GMA and VPK. Legacy LZMA
`.bin` alternatives are explicitly unavailable, preserving its normal default
conversion route. RAR/ZIP extraction and conversion-worker installation are not
added. No automatic installation, Steam writes, native assembly, runtime jiggle,
new shaders, timeline switching or signed/compound flex evaluator is introduced.
