This source-only preparation reads no active or completed00bf run outputs. It does not activate an archive builder. ## Proven source hazard

The current REVIEW `tests/verify.py:518–519` writes the entire nested result dictionary to `output/verification.json` and prints it. Therefore a successful `canonical.log` ends in the entire report. Individual wrappers also print nested verification reports. File extensions and successful exit status do not make logs public-safe. The current terminal helper copies `canonical.log` and `full-verification.json` into its audit folder (`close_terminal.py:225–226`); those copies remain PRIVATE, even if their folder is under `experiments`. The whole successful audit directory must never be staged or recursively archived. Root plans an exact ignore rule before executing that helper; publication remains an explicit allowlist.

The old52 full archive establishes the safer precedent: `native_five_full_actual_20261116/RESULT_EXTRACT.json` contains157 names,36 core scalar rows and21 movie scalar rows, while the raw2.3MiB report remains private. The new source requires158 names and12504 Neon checks, not a reuse of the old counts. A denylist such as `legacy_result_gates.reject_native_payload` is insufficient as a publication proof: it checks a few named mesh fields, but other legitimate nested poses/transforms/native measurements and complete source maps may remain. Use positive projection and exact schema/type checks instead.

## Concrete implementation prepared here

`projection_core.py` is pure in-memory code without filesystem/process APIs. `project()` checks exact registry/core/movie/Neon domains and returns only its written field allowlist. It never recurses through or stringifies omitted report values. It intentionally labels its result `PROJECTION_ONLY_NOT_A_FULL_VALIDATOR_OR_ACTUAL_RECEIPT`; codec metadata and complete158-group gate/physical receipt admission remain external requirements. `activate_archive()` always refuses. It supplies neither a native command nor a closed-output reader/builder.

Tests use authored RAM fixtures with secret canaries in ignored groups/diagnostics/snapshots, type/count/failure/extra-key/NaN mutations, missing case/predicate negatives and unconditional activation refusal. Source binding records compare the current REVIEW verifier/Neon fixtures and MAIN terminal/legacy/registry/old52 recipe before/after tests. No actual full results are read. A separately reviewed builder/verifier successor is required after root freezes the closed inventory; it must preserve the old failures and all original predicates rather than reinterpret public scalar extraction as full qualification.
