# Main/UI integration seam: deliberately not connected yet

## Existing boundary inspected

`src/secondary_helper_editor.gd:115` currently launches an authoring worker with `OS.create_process`, polls a PID in `_process`, and loads mutable `result.json`. `tools/secondary_helper_worker.py` atomically publishes that result file; it does not supply the trusted successful-exit pipe token required by this candidate. Its existing inspect/preview/review/build/batch_build/source_check operations and Apply/Undo install flow remain unchanged. There is no `tools/native_worker.py` in this project. `run.py` also probes/launches Godot, so this CPU-only increment does not call it.

## Small next integration increment

Add a preview-purpose controller entry point, separate from the existing authoring worker. It should import `OwnedPreviewJob`, accept bounded start/poll/cancel messages, own one `DraftLease` and one native child at a time, and forward only validated prepared-hidden events. The GDScript helper should own the controller's transport and lifetime and must receive an independently trusted successful-exit completion from it. Merely writing an additional `result.json` and rehashing it would lose the trust boundary established here.

A concrete transport option is `OS.execute_with_pipe` with nonblocking reads serviced by a Node, a bounded ASCII-line protocol, generation+nonce session, and controller-side EOF cancellation. The [Godot 4.6 primary API documentation](https://docs.godotengine.org/en/4.6/classes/class_os.html#class-os-method-execute-with-pipe) confirms separate stdin/stdout and stderr pipes, but explicitly says the process runs independently and survives Godot exit. Therefore that call alone is not a controller ownership solution. This packet has not exercised the API. Add and test a retained native ownership bridge or a proven controller parent-liveness/EOF lifecycle before integration; do not substitute `OS.is_process_running(pid)` or generic PID kill as proof. The Python adapter protects its one child, but does not itself make its controller owned by Godot. Preserve that distinction in the next design and tests.

First implement that transport with tiny CPU fixture work only: start success, cancel while gated/building, stale event after replacement, app/controller disappearance, both pipe caps, and exact cleanup receipts. Retain original helper/Apply behavior while testing this bridge. This avoids coupling native ownership debugging to a renderer or a private model.

## Follow-on helper gates after transport

1. Capture a read-only original actor context before preview: stable actor/root-instance string identifiers, recovery revision, frame, source identity, authored/shape/binding hashes. The existing `open()` freezes all physics; the preview path needs a separate non-mutating refusal/snapshot path, with live-physics/export/navigation guards rather than silently stopping or freezing original motion.
2. Produce focused-single or checked-batch requests from the already reviewed proposals and shape snapshot. Each checked item is reviewed against the original source. Proposal edits, selection/checked-set changes, source changes, frame/revision changes, close and replacement invalidate the generation. They do not consume Apply or mutate the existing request/install dictionaries.
3. After the owned worker is fully reaped and its receipt admitted, import its generated candidate hidden into a fresh owned candidate root. Supply **actual imported** source/candidate node-to-bone binding and complete base-transform snapshots to `imported_binding_map`; do not infer them from names or GLB metadata alone. The pure protocol's imported binding gate is available, but no Godot snapshot adapter is implemented here.
4. Build the candidate's isolated secondary-motion group catalogue and transfer original pose/body baselines only after that second gate. Only then may local-wind preview temporarily replace the original actor's visible representation. The original actor, authored springs, pose, simulation state, selection, recovery revision and Undo history stay unchanged.
5. On stop/close/error/context drift/scene replacement, synchronously invalidate both building and already prepared `DraftLease` tickets, cancel the correct generation, disconnect the owned callback/transport, restore original visibility and pose state, release candidate roots and caches, clear the canvas review pointer/box/lines, and reap owned processes before optional owned-directory cleanup. `OwnedPreviewJob.close()` only closes process ownership after success; it does not invalidate a prepared lease. Preserve current phase-1 local-wind guards, including canvas cleanup, and the separate world-selection callback lifetime repair.
6. Keep Apply as the existing separately confirmed authoring/install edit with its own original-source check and Undo. A hidden preview candidate cannot be installed merely because it prepared successfully.

## Current limitations

No GDScript source candidate, controller bridge, native extension, graphical import, real-model run, renderer or user interaction was added. Current Python controller tests validate one bounded ownership/transport layer only. Windows Job nesting or security restrictions fail closed on assignment; they are not worked around. There is no abrupt-controller-death experiment in this bounded run, and the `_handle` dependency needs a fresh compatibility gate for another Python runtime. Source/executable hashes are launch-bound local integrity checks, not an adversarial filesystem or interpreter proof.
