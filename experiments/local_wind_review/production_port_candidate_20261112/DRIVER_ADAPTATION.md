# Adapt the driver deliberately

The unchanged reference driver ran the isolated prototype and passed all six
jobs. **It is not a main-project verifier as copied here.** No adapted driver has
been implemented or executed in this preparation task.

- Put the future main verifier under `tests`, derive `ROOT` from that file's
  checkout, and bind its runner/project to `ROOT`. Remove the prototype-specific
  `BASE.parents[2]` and `BASE/'Studio'` assumptions. Require `runner.ROOT`, the
  command's `--path`, and a reported `ProjectSettings.globalize_path('res://')`
  to identify the same main checkout. Replaying the old private Studio proves
  nothing about a production port.
- Use a freshly reserved descendant of main's `output` for every run. Refuse
  existing destinations, traversal, links/reparse paths and overlap with protected
  reviews/recovery. Give every process fresh recovery, recent, display, workspace
  and unpack-cache paths. Keep source/test bytes immutable through a run.
- Preserve three separately reported modes: headless unit checks, four-script
  syntax preparation, and actual six-process GPU execution. Require explicit
  graphical selection and the coordinator's single-lease acknowledgement. The
  canonical invocation must choose the graphical mode deliberately; no parse-only
  default result or partial native skip can satisfy the six-case evidence gate.
- Keep the exact job order: procedural, VRM0, VRM1, derived Back hair, lifecycle,
  primary. Stop at the first unexpected failure and retain partial progress,
  process logs, commands, request/result files and private receipts. Keep the
  real app handlers and all numeric/data/pixel/ownership assertions unchanged.
- Replace machine-specific source-discovery paths with an explicit checksum-bound
  input manifest for the already approved fixtures. The current known prepared
  hashes are VRM0 `3caa50b76d0f481bb7ee66daeb6ebe7485aefb966140321b599ca60d9d464b56`,
  VRM1 `a0b095f399e0f7f95c88b91d12e74f8d1816052c1552b9d2dd758ceed8a6b062`, and
  ribbon-derived Reimu `4d62236d5c34468ea1f91c43089d6ce3c193be27b8460d53ea8d91d2238ab7b5`.
  Bind corresponding parameter reports and record original SHA/size/ns-mtime
  before and after. No asset payload goes into Git and no installed Steam content
  silently fills a missing fixture. A rebuilt fixture with different bytes needs
  its own reviewed provenance; do not silently accept any supplied hash.
- Copy inputs only into the fresh owned run. Preserve the existing backend's
  Back hair composition checks: retained ribbon, native joints11/10/9, two
  declarations, identical skin/binary/meshes/materials, zero changed vertices,
  and actual3regions/1369weighted vertices. Do not pretend those three regions
  are separately weighted wind groups.
- Capture all main functional source hashes/sizes/ns-mtimes and current revision
  before and after, including the actual main verifier and the sixteen port
  files. Bind runtime hashes to the reviewed port's exact bytes; explicitly record
  any Git checkout EOL reconstruction rather than ignoring code differences.
  Do not depend on an old prototype-only `runtime-review-reviewfixed.json` path
  or its original924-file snapshot to certify current main.
- Use the actual main `run.command` and private Windows launcher. Require zero
  process/assertion/engine/leak errors and every receipt's exit0, confirmed child
  desktop, no foreground child, closed job and closed desktop. Refuse visible
  fallback. Keep dependency preparation and all graphical processes serial.
- Report all six case counts, current project root, source identities, native
  preservation and PNG export scope. The known isolated run has830 checks, but
  don't use that total alone as proof; inspect actual case results and flags.
  Lifecycle's downstream recovery sink is an in-memory probe: it checks real
  queued GPU readback admission/pixels/counters, not persisted preview-worker
  output. Local/World Record is real start/cancel, not a newly encoded movie.

The optional one-procedural-case helper remains an unexecuted AST-checked local
diagnostic aid. It is not the main driver or a six-case acceptance shortcut.
