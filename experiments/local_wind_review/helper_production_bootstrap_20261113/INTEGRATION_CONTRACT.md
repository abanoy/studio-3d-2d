# Next integration contract

The bootstrap is implemented and exercised in the isolated Node. Normal callers supply trusted approved Python/controller paths and hashes, the actual helper source root, a fresh owned output root and a random session. They do **not** supply host creation identity. The Node derives its live process/image; the controller verifies and retains the host; ready must match before any submission. Main HAS has not adopted this class or controller yet. Keep engine/Python/source pins explicit and do not silently substitute another backend/runtime.

Start's small control envelope contains the session/sequence/current ticket and one `submission` reference with `path`, `sha256`, `bytes`, `context_sha256`, `source` and `source_sha256`. The referenced file has format `has_wind_preview_submission_1`, purpose `preview_only`, the same session and PRE-start ticket, original source path/size/SHA, checked reviewed items, context, exact ASCII `context_json`, and mode. Its raw hash, context hash and source binding are independently supplied by the Node's control, not recovered from editable data as expectations. `context_json` must decode to the stated context. A valid start creates a new worker draft generation and its separate request/receipt identity.

Poll carries only `context_sha256`, computed from the caller's current sorted ASCII context. If it differs from the admitted start context, invalidate rather than exposing cached work. First and cached prepared events also bind the original submission/context hashes. Cancel/close/edit/tree exit/EOF/host loss invalidate building and prepared tickets before cleanup. No request may consume authoring Apply, install a model, add Undo, or mutate original physics.

The next bounded main-source change should adapt this exact CPU host into a separate preview-purpose helper context, initially using the same self-authored fixtures. Preserve `src/wind_review.gd` guards/canvas cleanup, `src/secondary_helper_editor.gd` existing authoring/Apply/Undo path, and the unrelated `src/world_selection.gd` callback lifetime repair. Review the controller's source root and owned output family against the application's packaging/layout rather than assuming checkout paths. Existing authoring workers' `result.json` is not the trusted preview completion transport.

Before exposing a candidate, capture the real original actor/root/revision/frame/source/authored/shape/binding context without freezing or editing it, and connect synchronous invalidation for helper edits, checked-set changes, save/scene replacement, revision/frame/source/shape/binding drift, export and incompatible live motion. Actual UI ownership should keep the Node's process-map entry exclusive and single-use. Do not broaden mapped cleanup to Encoder, SourceImport, existing `OS.create_process` workers or arbitrary PIDs.

Only after main-app CPU hosting and lifecycle checks pass should the candidate be imported hidden into a fresh owned root. Obtain actual Godot source/candidate node-to-bone maps and full base transforms, then apply the prior imported binding gate. Only then build isolated local-wind candidate groups, transfer the original baseline and temporarily replace its visible representation. Restore original visibility/state and clear canvas hooks on stop/error/close. These import, simulation, original-state and rendering gates remain unimplemented here.

Retain the 2048-byte control and 1 MiB file limits. A source/reference path too large for the small envelope is refused; do not raise the pipe cap without new evidence. The Node allows at most 128 publication attempts and never overwrites a published request. Request files are local integrity artifacts in an owned family, not an adversarial multi-writer database. Future packaging, other runtimes/engines/backends or broad filesystem threat claims require their own tests.
