# Remaining app integration

This packet removes the earlier need to assume a compiled native extension just to test controller lifetime. Standard GDScript plus the exact pinned Windows process-map branch and the independent Python watchdog suffice for the demonstrated CPU fixture. Keep those proofs narrow: successful own launch, one exclusive map owner, one consumed-before-call cleanup, no other component calling `OS.kill` on that PID, no retry even after `FAILED`, and no widening to unrelated `OS.create_process` helpers or arbitrary app PIDs. Porting to another engine/runtime/backend requires fresh source and native tests.

The actual Node currently receives exact host creation identity from the external fixture observer. A production bootstrap has not been implemented. A concrete next option is a trusted pinned Python controller opening the still-live Godot PID once, retaining it, reporting host PID/creation plus the verified Godot image path/SHA in ready, while the Node compares that PID with its own still-live `OS.get_process_id()` before any start. This needs a separately reviewed, bounded bootstrap protocol and actual tests; the current mandatory creation argument is not silently weakened here. There is no invented GDScript WinAPI or native creation-time method.

Before connecting a real helper window, adapt the bounded Node transport to actual scene context and confirm main-app lifecycle without importing a private model. Preserve `src/wind_review.gd` phase-1 guards/canvas cleanup, the existing `src/secondary_helper_editor.gd` authoring/Apply/Undo behavior and the separate `src/world_selection.gd` callback lifetime fix. The Node should remain independent of the existing helper's mutable `result.json` authoring transport.

The fixture has one outstanding command and rejects a frame above 2048 bytes. Product batch/patch requests may exceed that. Do not silently raise the cap or retry a partial write. Either prove bounded pipe backpressure/partial-write behavior on the supported runtime or use a separately reviewed chunked framing protocol with explicit completion and budgets. Standard pipe EOF/flush helpers have pinned-runtime quirks captured in the primary evidence.

Only after actual app CPU hosting is accepted should preview-purpose preparation import a candidate hidden into a fresh owned root. Capture original source/actor/root/revision/frame/authored/shape/binding context read-only. Obtain actual Godot source/candidate node-to-bone bindings and complete transforms, then run the prior protocol's imported binding gate. No source labels or GLB metadata may substitute for actual imported bindings.

After that second gate, construct isolated local-wind candidate groups and transfer the pose/body baseline without editing the original. Helper edit, checked-set change, close, save, source/frame/revision/shape/binding drift, scene replacement, export and incompatible live motion must synchronously invalidate the ticket before queued callbacks can expose a candidate. Stop/error/tree exit restores original visibility/state and clears canvas hooks. Preview cannot consume Apply, install a model, write Undo or alter original authored springs. Those UI/import/simulation/render behaviors remain unimplemented and untested by this packet.
