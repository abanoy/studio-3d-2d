## Preserve the three independent choices

The focused region is a refinement cursor. **Include in setup** supplies the candidate's reviewed setup requests. Temporary wind checkboxes operate only on the actual derived candidate's declared motion groups. A wind-unchecked setup remains built, with its original authored baseline; focus alone never enables wind. Empty setup membership uses the existing precise focused-single request. Do not alter authoritative requests, included.valid flags, setup membership or Undo when copying requests into a preview envelope.

The worker protocol purposely has no temporary wind-selection argument. It builds every included request. Shared native joint setups may deduplicate to one declaration with several source regions; several visible rows therefore need not represent independently controllable wind groups.

## Increment1: protocol adapter and read-only context, no renderer change

Add one `preview_build` operation to an owned helper worker adapter, using this candidate module. Its fresh folder must be a descendant of an explicitly owned `output/wind-helper-drafts` family. `request.json` is written exclusively before launch, and its **actual bytes** are SHA-bound; do not expect Python/Godot JSON serialization to produce the same canonical float text. Existing helper assessment supplies the exact nanosecond source stamp string. Capture source/root/owner identities, recovery revision, fixed frame, authored-world digest, full static shape snapshot and source binding snapshot while the UI is valid and idle.

Serialize object/root IDs and stamps as strings. Every setup item must already be valid and reviewed against the same original source and shape choice. Build from copies. The adapter waits for its **owned process exit0** and captures its separate completion result/pipe containing generation, nonce, request digest and exact receipt digest; a file appearing while a process is still publishing is not completion. Do not derive the expected receipt hash from the same editable receipt file at admission. Keep a single owned worker slot, generation and nonce. On edit/close/seek/save/Record/export/replacement/timeout, synchronously invalidate the token first and remove/hide any displayed candidate before further authoring/capture. A queued new inspection may start only after the old owned worker has exited. Do not kill a generic PID or remove a live job folder. Late files remain private and are not installed.

This output candidate does not supply the process/job-handle wrapper or a GDScript ticket. Its DraftLease is a tested CPU reference, not a pretend cross-language runtime. The next patch must implement those exact state transitions in a Node-owned controller without suspended coroutine waits, and verify ownership/timeout/close on headless tests before graphics.

For full-nanosecond source freshness after an asynchronous build/import, run the existing source_check operation or a narrow protocol check around import; GDScript's FileAccess.get_modified_time only gives seconds and cannot certify the ns stamp alone. Keep a prepared model hidden until the post-import check and generation/context validation pass.

## Input, capture and cleanup ordering

1. Refine mode owns the existing helper part/patch pointer. Before warming/running, cancel a pending patch/part press, release its pending world-selection gesture, and clear helper review_lines/review_chain while retaining draft data. Clear the pose arrays as phase1 already does. Existing phase1 stop/gizmo cleanup is preserved.
2. Running mode owns navigation-only scene input; no part/patch edit occurs on the temporary model. Keep Ctrl/WASD/middle/right and off-frame rejection. Source refinement gestures first stop/invalidate the preview, then revise the source request.
3. Stop restores original mesh visibility, disposes only the private solver/candidate, disconnects its warm-up callback, and releases only its own pointer. Reproject the original helper overlays only if the helper/context/pointer still exists and no newer owner has acquired input.
4. Helper close stops wind before releasing the helper pointer/window. Exit/remove/queue_free paths must clear both candidate and all source/candidate snapshot references. Use Node-owned callbacks; do not introduce nested frame-post-draw coroutine chains.
5. app.stop_local_wind, final renderer capture, recovery admission/completion, save, Record and asset replacement must invalidate **building/prepared** helper tickets too, not only warming/running. A late worker must not restart a preview after an operation ends. Building a hidden candidate alone does not alter pixels; showing one changes the existing phase1 generation interval.

## Apply remains an authored transaction

Stop/invalidate the temporary preview before considering Apply. If any real simulation or pending physics creation is present, refuse Apply safely with an explanation. Recheck this after an asynchronous Apply build and before install. Do not auto-freeze bodies or consume a history item. When stopped with no active physics, keep the existing immutable asset, one Undo/Redo transaction, source/shape/history validation and portable save behavior. Supporting Apply while live physics continues requires a separately reviewed transaction and is outside this increment.
