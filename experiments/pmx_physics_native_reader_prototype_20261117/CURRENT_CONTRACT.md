# Current prototype contract and preliminary-design differences

`LAYOUT.md` and `SOURCE_BINDING.json` are exact historical copies of the independently sealed layout design. Their statements that no parser was implemented, their suggested128KiB capsule, and their suggested finite-only physics policy describe that earlier design. They are not the current implementation contract. The actual code in this packet implements the following narrower read-only metadata prototype.

- Input is immutable in-memory `bytes`; no file, texture, external dependency, installed addon, engine or network is opened by the parser. PMX2.0 only, exact signature/version/global length and exact final EOF. PMX2.1, trailing soft-body data and unknown layouts refuse.
- Geometry, texture/material names, morph records and display frames are bounded prefix traversal used to locate native physics tables. They are not returned geometry, a full PMX validator, a native dependency join, or a valid rendering/skin/IK assertion. Material face coverage is intentionally not established. Strict selected tags/flags/counts/index ranges are traversal guards, not complete semantic validation.
- Native bone catalogue and optional bone/IK payloads, body/joint names, all physics raw binary32 words, signed native references, unsigned collision masks, native table indices, byte spans and complete sourceSHA are retained. Duplicate and empty names remain distinct through native table indices. No name matching or HAS bone identity is inferred. Output has explicit F32 field-word layouts; no physical value is scaled, repaired, normalized or rounded.
- Bone and physics binary32 words are opaque little-endian hex. Negative zero, subnormals and NaN/Inf payloads are preserved; nonfinite word indices are explicitly classified. JSON output contains no numerical NaN/Inf. No finite-value, simulation-validity or physical-plausibility qualification follows from this raw capture. A downstream finite physics profile would require a separate explicit validator.
- Source cap128MiB; per-string1MiB and aggregate decoded-prefix input string bytes8MiB; retained names1024 UTF8 bytes each; output canonical compact metadata cap2MiB. A conservative retained-metadata reservation also refuses before accumulating the corresponding output structures. The exact final JSON size is checked independently. Entry and operation caps additionally bound work and object counts. There is no128KiB,256KiB report or1MiB portable-fit claim.

All budget values in `Limits` are explicit hard ceilings and caller overrides may only reduce them, using exact Python integers. Default caps:2M vertices,12M face indices,10k textures/materials,4096 bones/morphs/display frames,1M aggregate morph offsets,65536 aggregate IK links/display elements,512 bodies,1024 joints and20M cursor operations. The parser is allowed to refuse a valid but out-of-profile source. No truncation or partial capsule is returned on refusal.

Signed-reference policy is field-specific. Minus one is accepted as raw layout absence for vertex-weight bones; material texture/sphere/unshared-toon references; bone parent/tail/grant and IK target/link references; material morph's all-materials reference; body bone; and joint source/destination. This broad prefix absence policy does not assert valid weights, grant semantics or IK. Minus one is rejected in group morph, bone morph and display references. Vertex references are unsigned. Every other negative signed word refuses, and every nonnegative reference must be below its table count; vertex-weight bone references are checked once the later bone count is known. No negative word is collapsed to None or zero.

Known initial selectors: vertex BDEF1/2/4/SDEF only; material flag bits0..4 and sphere modes0..3; shared-toon flag0/1 with shared toon0..9; bone flags subset0x3f3f with IK limit byte0/1; morph category0..4 and types0..8, material operation0/1; display special/tag0/1; rigid group0..15 and shape/mode0..2; joint mode0. These are explicit restrictions of this prototype, not a complete statement of every PMX extension.

Native-file qualification, decoded-capsule joins, HAS standardization, physics reconstruction/simulation, scale normalization and integration remain UNIMPLEMENTED/UNQUALIFIED. No native asset was read for these synthetic tests.
