## Visible behavior

A prepared static Junko assembly is one group in World with six direct model children. Select the root or a child and use World → Manage parts, or right-click visible member geometry → Manage parts. The World action remains available if every part is hidden. The dialog shows all six retained pieces with independent checkboxes. Dress only, Skirt only, Miniskirt only and No clothes parts buttons are single-part shortcuts; checkboxes can intentionally layer clothes. Apply writes all changed visibility states at the current frame in one existing world_objects Undo transaction. It does not delete hidden assets, modify poses/morphs/physics, or replace any part source. No-op applies create no history. A changed session, sequence owner, video, frame/world or active editor/physics/import operation refuses the edit.

The host install_bundle API accepts the already prepared six rows, one real empty group GLB and one common conversion policy. It uses existing app.restore_world preflight/installation, followed by one world history entry; a failure never installs a partial set. It pins and inspects the root asset before installation: only plain empty identity-transform Node3D nodes are allowed, with no geometry, skeleton, light, camera, animation or script. Existing SceneIO.make_empty supplies the real inert GLB. A world_objects transaction is deliberately not used to reparent: the existing restore_instances API correctly refuses parent changes.

The six native MDL hashes are explicit admissions from the retained audit. Their provided converted GLB hashes and caller-declared common policy must remain identical in the part binding. This module does not open or authenticate an MDL or certify a converter receipt. The import host must verify the ordinary conversion provenance and same-origin policy before calling it. It accepts fresh, independent, unanimated root transforms only; already scaled/recentred/parented parts and active import-basis lineage refuse instead of being silently reset. Moving/scaling the group then moves all six prepared source origins once. Rig/bone inventories, native metadata, local morph data and procedural ownership remain separate.

## Units and body reference

The common policy records metres per Source unit with units_already_in_glb=true and retain_prepared_roots. That conversion factor is not multiplied into the root or each actor again. Each part starts at scale1 and the one explicit whole-character factor belongs to the group. suggest_body_scale derives an unapplied1.8288-metre suggestion from one complete-body height; it claims neither body classification nor a verified import basis. Hair, masks and clothes are never independently height-normalized. The existing active asset_basis contract permits character models, not group roots; this prototype does not forge a new bundle six-foot capability or claim that a visible group scale factor is already the standard Scale1 workflow.
